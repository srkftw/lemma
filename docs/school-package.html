Reusable school packages

A reusable school package is a versioned definition that can initialize a separate school. Lemma.School.Definition.Package records immutable authored publications, explicitly reusable model releases and the supported resource and policy requirements. It has no school, deployment, operator, learner, credential, grant, lease or execution-generation fields. Instantiation supplies a new school identity, deployment identity and owner.

Export and instantiate

With an initialized school at build/my-school, its owner or an actor granted publish on school can export to an unused package directory:

scripts/lemma-school build/my-school '{"op":"definition-export","school":"school-a","actor":"owner","to":"build/my-school-package"}'

Use the actual school and actor identities from that authority. The receipt reports the package JSON digest, publication count and reusable-model count. The directory contains school-package.json and content-addressed bytes under artifacts/; transfer that directory together. The package is reusable independently of the original running authority.

scripts/lemma-school build/independent-school '{"op":"init-package","school":"school-b","actor":"new-owner","deployment":"deployment-b","from":"build/my-school-package"}'
scripts/lemma-school build/independent-school '{"op":"status","school":"school-b","actor":"new-owner"}'

The destination must be fresh; the transport's mutex file alone is permitted. Installation rejects an existing initialized school or unrelated contents. It strictly decodes the definition, verifies and copies required artifact bytes, runs the ordinary publication and model-registration admission paths, restores an included selected model, and makes one final authoritative state commit. A failed admission does not publish a partial school state. Artifact bytes left before a failed final commit do not establish publications or authority.

The default clock is monotonic-ms. The explicit controlled-ms clock option is for deterministic tests. The new owner's authority comes from local initialization. Other grants, enrollment, source-location overrides and execution configuration require explicit setup in the new school. The current identity boundary is the documented local caller and operator filesystem; these commands do not provide production authentication.

One validated definition and its bytes

The package schema is lemma-school-package/1, version 0.1.0. Each publication contains its complete Authoring.Unit, publication-policy version and course artifact digest. Validation checks that unit, compiles its guest course through Authoring.compile, and requires the resulting bytes to match that digest. Source anchors and activity policies remain in the validated authored definition; the course artifact uses the existing guest package format. Unknown nested fields are rejected rather than silently dropped.

Model releases carry a version, parameter-artifact digest, dependency-artifact digests, rights/provenance statement and explicit reusable=true. The parameter digest is separate from its 1–32 dependency digests. Only releases explicitly marked reusable are extracted from live state. Selection is retained only when that release is included. The effectful installer additionally checks the supported parameter, numerical-profile and synthetic-dataset contracts through ordinary model registration; descriptor metadata alone cannot admit arbitrary model bytes.

Version 0.1 supports the local provider, worker profile core0-v0.5, tutor policy lemma-authored-assistance/1, learner model school-linear-q10-v1 with baseline, and closed permissions with explicit grants per school. Unsupported requirements, invalid budgets, duplicate identities, missing reuse statements and mismatched artifacts fail admission. There are at most 128 publications, 32 reusable releases and 1,024 distinct required immutable artifacts. Resource budgets remain within the maintained school limits.

Sources and transfer boundaries

Source registries, edition identities, anchor verification and file digests remain part of each immutable authored unit. Source text files are external dependencies and are not automatically bundled as course or model artifacts. An owner's location already written into an authored source manifest remains metadata in the package; package extraction is not a scrubber for arbitrary authored content. Review that metadata and its declared rights before distributing the package. A reuse flag or rights statement is an owner's assertion, not independently verified permission to redistribute a textbook.

Deployment-specific source-config overrides are excluded. After transfer, an authorized publisher can use source-config to bind the retained source digest to a new owner-controlled file path. source-resolve verifies those bytes before returning a location. Missing source context is recoverable through that explicit operation without changing the immutable published definition. See the source and authoring guide for the request fields and actual corpus evidence.

Content hashes detect changed bytes under the local storage contract. Package JSON and provenance statements are unsigned; these checks do not authenticate an external publisher. Package export carries neither private learner history nor live permission records. It also does not provide deletion, unlearning, source licensing, sensor transport or a claim of educational effectiveness.

Verification

nix develop --no-write-lock-file --command python3 -m unittest discover \
  -s tests/school -p test_definition.py -v

The focused tests execute the actual pure Lean extractor and validator. They exercise a live-state fixture containing private history, credentials, source overrides and both reusable and private model releases; verify that only the supported reusable definition is extracted; check strict decoding and compiled-artifact binding; and retain a maximum 32-dependency model closure. The current-source receipt is summarized in the definition validation evidence. These pure tests do not claim effectful installation. The maintained authority tests separately exercise export, fresh instantiation through the mutex transport, independent artifact copies, empty learner progress, unsupported requirements and occupied destinations.
