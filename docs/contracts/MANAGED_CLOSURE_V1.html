Managed unary scalar closures v1

lemma-managed-closure-v1 adds core0-user-v0.7 and the distinct Action.managedClosure2 bridge. User1–6 retain their grammars and reject this bridge. User7 inherits their existing bridges, execution operations, privilege boundary and fixed virtual address domain. No production deployment selector, mathematical verifier, proof kernel or persistent document format changes.

A direct safe monomorphic ordinary Lean UInt64 → UInt64 → UInt64 entry is elaborated by pinned Lean4.34.1 at immutable compiler revision 5045d0056413266e57c625dcd7c365b10e377c52. Reachable ordinary functions accept only UInt64 and unary UInt64 → UInt64 parameters and return UInt64. The actual compiler IR decides ownership and control. There are at most32 ordinary source definitions, acyclic call depth8,8 distinct PAP targets,4096 IR nodes per source function, and65536 generated SSA IDs. Source SSA IDs are unique and below10000.

The reserved generated namespace and the dispatcher source name __apply cannot be impersonated or collide with an ordinary source declaration.

The new grammar admits actual box UInt64, unbox, pap, unary app, owned single-reference inc/dec, exact exhaustive Bool control and closed direct ordinary calls. Scalar add/subtract/multiply/bitwise operations use all64 bits with unsigned wraparound; shifts mask the count to0–63. Source-local ownership is affine: an owned local has at most8 compiler-visible references, consuming calls decrement them, reads after consumption and leaked roots reject. Closures never escape this scalar entry as unchecked handle words.

A PAP target must be the actual generated _boxed adapter of an admitted ordinary scalar function. It has1–5 object parameters, no borrowed parameters, and one object result. Its genuine body must unbox each parameter as UInt64, consume it once, call exactly its safe source owner with those scalar values in order, then box and return the full UInt64 result. The compiler checks actual parameter/body IDs, ownership metadata, source ownership, arity and layouts. The exact source type, owner identity and generated adapter IR are exported; there is no manufactured source declaration for the adapter. pap must leave exactly one invocation argument and consume0–4 owned scalar boxes.

The maintained backend does not import the upstream runtime. The immutable upstream IR/EmitLLVM.lean lines713–750 and LCNF/EmitC.lean lines665–683 emit lean_alloc_closure, captured object fields and lean_apply_1; upstream runtime/apply.cpp lines101–157 distinguishes exclusive/shared closure roots and retains captures for shared application. This unsupported foreign path is replaced by a checked Lean-authored source-derived finite CFG dispatcher. Its code catalog comes only from the checked actual PAP adapters. It checks the code ID and capture count, reads the full scalar captures and argument, calls the exact checked source owner, consumes one closure/argument reference, then allocates a real result box. It is neither a target interpreter nor a lean_apply/allocation stub.

Scalar adapters cannot observe object identity/refcounts or escape a capture. Therefore their temporary shared-capture retain followed immediately by unbox and dec is represented by a validated borrow from the live closure root. Shared closure application decrements only that actual parent. Final application releases its owned captures and parent. This specialization preserves the checked adapter's scalar values and ownership while using the versioned arena's explicit resource policy, rather than pretending its object ABI matches the upstream heap. Persistent/static boxed captures and initializers reject; they are not tokens, truncated words or no-op reference counts.

Real storage and lifetime

The runtime uses lemma-owned-arena-v1: one syscall-owned process page at 0x400000, a128-byte header and31 slots of128 bytes. Each full UInt64 capture is a real8-byte scalar box. Each closure is a real64-byte bytes-tagged object whose inline owned environment has this layout:

Payload offset Field
0 Cookie 0x31534c4341524d4c
8 Checked source catalog code ID1–8

Slot headers retain the existing state/generation/refcount/tag/length fields. Every observation validates the page header, live count1–31, slot, generation, refcount1–65535, bytes tag/length, cookie, code/count, used boxed children and zero unused/reserved fields. Retain increments the actual parent refcount. Shared release decrements only the parent. Final release preflights each child, releases every capture, clears/regenerates the parent slot and decrements the actual live count. Cancellation blocks observation/allocation but cannot block owned cleanup. Child boxes may be aliased only through real retained references.

A k-capture closure owns k+1 slots. Application temporarily requires an actual argument box; its actual result box is allocated after consuming the argument and one parent reference. Multiple live closures and intermediates share the31 slots. The source budget is not a promise that all admitted inputs fit: actual exhaustion returns237 and publishes no scalar result. Invalid shape/code/index returns236, cancellation238, and lifetime failure239; mapped-memory and syscall faults retain their actual status. PAP rejection/OOM consumes its captured roots. Failed calls clean up remaining owned locals; cleanup attempts all owned roots while preserving the original failure. An actual memory fault can defeat cleanup and is never reported as successful rollback.

There are no generic closures, closure-valued captures, escaping closures, multi-argument/over/under application, static closures, join points, reset/reuse, polymorphism, recursion, arbitrary externs, dynamic source bridges or proof execution. Those remain separate work.
