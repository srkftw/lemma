lemma-exact/1 checks signed rational addition equality and univariate product identities over Q[x]. Signed integers use canonical sign/magnitude u64 words: bit63 denotes negative, bits0–62 magnitude, and negative zero rejects as NeedsClarification. Public magnitudes and positive denominators are at most 1,000,000. Zero denominators return Invalid before arithmetic; exceeding the declared representation returns Indeterminate. Rational cross products are bounded by 2×10^18 and polynomial intermediates by 2×10^12, below bit63. No wraparound, floating-point comparison, parsing success or host invocation can authorize Verified.

The rational request is a/ad + b/bd = n/d, with explicit nonzero positive denominators and an eight-step budget. The polynomial request is (a*x+b)*(c*x+d) = p2*x²+p1*x+p0, requiring six steps. Equality checks the exact three coefficients, rather than sampling x. Smaller budgets return Indeterminate before arithmetic. The public outcomes are Unchecked0, Verified1, Invalid2, NeedsClarification3, Unsupported4 and Indeterminate5. The arithmetic budget is a deterministic semantic resource bound; it is separate from kernel scheduling, stack, process death and host deadlines.

The original lemma-course-arithmetic/1 package has fraction addition 1/2+1/3, then expansion (x+1)*(x+1). The third page is an explicit Unsupported example. Text and exercises are original; source/edition/rights anchor is Lemma/Courses/Arithmetic.lean. Fraction equivalence and distributivity are logical prerequisites; fractions then products is the pedagogical order. There is no external textbook dependency, package installer or live tutor.

The pen-driven panel edits explicit typed numbers0–99 separately from raw ink. Selection never interprets handwriting. Closing the panel reconstructs the unchanged page from original ink. Ink outside the panel remains ordinary ink. CHECK calls the guest arithmetic algorithm on the actual current answer; NEXT changes the immutable goal identity; HINT records explicit assistance and displays an authored local hint; LIMIT selects the eight-step or zero-step budget; CLOSE hides the panel. The explainable baseline recommendation is Practice after Invalid/Unchecked, Review later after Verified, or Needs support after other terminal outcomes. This is an uncertain practice suggestion, not evidence of learner understanding, retention, transfer or learning gain.

Launch and interaction

Build the maintained canonical development notebook and prepare the same audited image for the native fast machine:

nix develop --no-write-lock-file --command python3 scripts/build_kernel.py \
  --configuration lemmasim-silicon-power-notebook --stage supervisor \
  --opt-level O2 --output-dir build/kernel/my-course-notebook --timeout 300
nix develop --no-write-lock-file --command python3 scripts/audit_kernel.py \
  build/kernel/my-course-notebook
python3 scripts/lemmasim build --backend qemu --profile lemma-silicon-dev/0.3.0 \
  --workload notebook --guest-build build/kernel/my-course-notebook
python3 scripts/lemmasim session --backend qemu --profile lemma-silicon-dev/0.3.0 \
  --workload notebook --disk my-initialized-notebook.raw --session-dir build/my-course-session

This is the explicit ELF-preload development path, not product boot/update. Use an already initialized notebook medium; opening does not format user media. Tap COURSE below the notebook toolbar. Select N/D or C0/C1/C2 in the FIELD row, then use PLUS/MINUS to edit the typed number. For 1/2+1/3, enter N5/D6 and tap CHECK. NEXT selects the polynomial exercise; C0=1, C1=2, C2=1 checks its exact identity. HINT records assistance from the authored local course. LIMIT selects the explicit zero/eight-step budget. CLOSE returns to the original ink.

The connected raw-input/durable/cold observer, with original declared bounds, uses a private copy of its input medium and unused output path:

python3 scripts/check_math_session.py --disk my-initialized-notebook.raw \
  --work-dir build/my-course-observation --deadline 2400

It checks actual guest results, edit invalidation, immutable history, explicit assistance, resource/unsupported outcomes, raw ink retention, controller pixels, acknowledged bytes, independent cold reopening and a failed save. It does not exercise a live tutor, managed runtime or Lean proof-kernel checking.
