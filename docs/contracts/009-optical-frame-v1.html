Representations and clocks

Three raw image endpoints use the synthetic common100MHz acquisition clock/reset domain. Endpoint1 admits the existing16×16 U16_LE synthetic shared eye/fiducial plane or160×120 Gray8 eye-region pixels. Endpoint2 admits160×120 Gray8 eye-region pixels. Endpoint3 admits320×240 Gray8 face-region pixels. Gray8 strides are exactly160/160/320 bytes; the U16 stride is32 bytes. The maximum payload is76,800 bytes and the complete header-plus-payload record is77,056 bytes.

The economy reference is two160×120×60Hz Gray8 streams (2,304,000 bytes/s) plus320×240×15Hz Gray8 (1,152,000 bytes/s). This declares supported representations and a requested schedule, not measured sustained acquisition. The complete base workload remains3,902,720 bytes/s and is open until actual mixed controller/consumer execution is qualified. Stress320×240 eye/640×480 face representations are not admitted by this first controller. There is no implicit downsample, Gray8-to-U16 conversion or RGB collection. OpticalDerived/1 can process only the explicitly synthetic16×16 U16 source; every derived output retains the raw source identity.

The device uses source ticks, exposure start/end, actual accepted EOF availability and later DMA completion as separate observations. A header never obtains timing from a User-supplied value. The driver rejects ticks beyond the admitted signed virtual-clock domain. Controller completion is not measured optical onset; the synthetic fixed-plane calculation is not per-eye gaze, anatomy, affect or learning evidence.

Raw source handshake and ordering

The environment supplies a ready/valid source endpoint1..3, kind,64-bit data, byte count0..8 and16-bit quality. Kind0 SOF has no data; kind1 DATA has1..8 little-endian source bytes; kind2 EOF has no data; kind3 GAP declares a positive count of source frames lost before delivery. The producer holds all fields stable while valid and not ready. This is the sensor-side digital boundary, never User MMIO or a processed region/result. No host code creates document anchors, derived coordinates or a successful acquisition receipt.

A valid SOF latches acquisition epoch, configuration, consent, gain, format, geometry, exposure and calibration. Capture start is the actual accepted SOF tick; capture end is start plus configured exposure. DATA contains declared post-converter digital source codes in the selected format. DATA may contain any1..8 bytes and may split a U16 pixel across beats or cross rows. The controller retains a low byte until the complete little-endian pixel exists; no padding is synthesized and EOF with a dangling byte is truncated. The controller applies digital gain1..64 only to a complete pixel, clamps to255/65535 and reports saturation; this is not an analog detector integration model. DATA readiness enforces the exposure end plus the last affected row's configured delay. SOF period spacing and EOF's complete row schedule are operational gates. Exact payload length, byte order and EOF are required. Available is the actual accepted EOF tick, which may differ from the nominal exposure-plus-row schedule. Missing/truncated/extra data and source gaps are explicit faults or quality observations; they never become a valid complete frame.

At each100MHz edge, a previously held memory completion retires first, then reset/link/consent/lease fences apply, then source input is considered, then MMIO. A held memory transaction keeps address, direction, data and owner stable. A revoke may leave an already accepted physical write prefix; that slot is unavailable to User delivery and cannot be reused or wiped until the held transaction retires. New permissions never authorize completion of an old capture.

The native Developer/Laboratory action optical-source-batch queues raw source words at the current cycle without advancing the clock. It accepts at most65,536 ASCII bytes and1,024 newline-separated five-u64 rows; the entire batch and capacity are validated before any row is appended. It requires the exact profile17 optical execution binding and ABI1. Student injection is refused. The canonical input-event spelling is <cycle> optical-frame endpoint kind data bytes quality. The browser generator uses the shared raw-source helper for512-,19,200- or76,800-byte patterns only. Neither transport constructs headers, capture timestamps, document anchors, permissions or derived coordinates. Queuing these digital bytes is not sensor, DMA-completion or throughput qualification.

Controller discovery and owned scatter/gather memory

The separate aperture is0x10016000..0x10016fff, IRQ20. Discovery magic is0x4c4d4f31, ABI1. This does not change the existing MM1/MM2 register aperture. Only a new kernel/Notebook26 deployment grants the optical capability.

The kernel allocates two lifetime-owned data slots per endpoint from owner1/purpose1 frames:5+5+19 pages per set,58 data pages total. One private descriptor page contains six256-byte slot descriptors, ordered endpoint1 slots0/1, endpoint2 slots0/1, endpoint3 slots0/1. Each descriptor has pageCount, capacityBytes, nonzero slotGeneration, reserved0,19 physical page addresses and nine zero reserved words. Unused addresses are zero. Capacity is exactly pageCount×4096; page counts are5/5/19. Pages are aligned, within the checked32MiB pool, distinct across the whole table and disjoint from every control/history/scratch page. The kernel derives them through actual owned frame handles; no User pointer is a DMA address.

The controller reads and checks the table before accepting acquisition. It does not follow a mutable User descriptor. The hardware rejects data-page aliases and the table page; the kernel separately verifies that data pages do not alias its other control/history/scratch pages. Table changes are refused while a source frame, queued frame, User-delivery lease or held DMA operation owns any slot. A ready frame header is published only after all payload and header writes complete successfully. IRQ is level-triggered for ready frames or explicit faults. Consuming a frame requires its exact head sequence; status reads do not acknowledge, discard or relabel it. Valid DATA backpressures at timing/packing bounds. A structurally valid exact-length EOF also backpressures until its complete row schedule and prior payload packing/writes retire; malformed/truncated EOF is accepted and faulted. A SOF with full slots is explicitly dropped and its data discarded through EOF with a loss/error observation; it never overwrites an old frame. Reset, link loss, expiry, revoke and counter exhaustion cancel publication and preserve held-operation ownership until retirement.

One global User-delivery lease pins an exact ready head, slot, generation and consent. Expiry/revocation changes it to revoked rather than releasing the referenced pages. They remain unavailable to new source capture until the kernel retires its synchronous copy reference and explicitly cancels/releases the stored lease. Staging cannot retarget a live or revoked lease. Only the kernel's exact completed User cursor authorizes consume; direct endpoint consume refuses a pinned head. A held write must also retire before reuse. Slot generations, acquisition/configuration identities and counters never wrap. Equipment POR alone seeds controller epoch1. Accepted complete SG table publication/retirement and each asserted ordinary reset event advance it once; holding reset asserted does not repeatedly advance it. Ordinary reset preserves source/completed sequence, configuration, consent and slot-generation floors. MAX exhaustion fails closed without wrap or new publication; service grants bind the actual current epoch.

Equipment power-on initialization is distinct from ordinary/domain reset and Coldcycle. Ordinary reset retains any accepted optical external-memory request until the existing fabric actually retires it, invalidates old capture/READY authority, and explicitly discards queued unaccepted ingress with an observable transport count. Before any frame allocator reinitialization, the kernel waits for the actual held DMA owner to retire. A new kernel boot may release an orphaned revoked delivery lease only after the actual CPU/fabric reset fence retired the old synchronous copy owner, held136 is0, inhibition is1, all current grants are0, and the nonzero ordinary-reset witness240 equals controller epoch80. It issues stored lease cancel/release3 and rechecks delivery208=0 before allocation. A live lease1, missing/mismatched witness or unfinished copy never permits release. The reset witness is0 after equipment POR or failed epoch advance. Descriptor generations are reseeded from each retained slot generation floor plus1; service grant epochs are reseeded from endpoint24 retained consent floor, rather than current grant112 which is0 after revoke. Exhaustion refuses optical authority without wrap; once old owners retire, unavailable optical hardware must still permit the basic pen-only Notebook. At counter exhaustion only, a separate hardware-only ordinary-reset fence248 permits the new kernel to retire revoked lease2 after the old CPU copy and held DMA retire, with inhibition1, all grants0, invalid table and controller error14. Explicit cancel/release may clear that lease while the MAX-generation slot remains cancelled/faulted and every future optical table/grant/DMA is permanently refused. It does not fabricate a valid epoch or new frame. The fence is0 after POR and clears before any new authority; lease1 and active-table states never qualify. Public snapshot/restore for the new optical binding refuses before mutation until pending source, SG, lease and viewport state are qualified.
