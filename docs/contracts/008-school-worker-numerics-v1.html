School numerical reference and RV64 worker v1

This version implements hosted Lean training of a bounded two-feature linear risk scorer and freestanding RV64 inference from its runtime parameter artifact. It preserves Core0 v0.5 and its fixed checked-RAM/UART profile. The separate application contract is lemma-school-worker/v1; its numerical contract is school-linear-q10-v1. The new school-worker build category does not change a historical test-suite ABI.

Implemented numerical language and allocation

Lemma.Numerics.Tensor exposes explicit two-dimensional shape, binary64 dtype and row-major layout. The hosted reference owns a Lean FloatArray, whose upstream runtime stores contiguous binary64 elements with value semantics. Every admitted tensor has positive dimensions, exactly matching storage, finite elements and at most 4096 elements (32768 payload bytes). Checked construction and each operator revalidate these limits; malformed shapes, nonfinite input and nonfinite results reject. Addition, elementwise multiplication and row-vector dot product are implemented. The fixed linear computation uses two-feature dot, bias addition, half squared error and their specialized reverse pass. Other operations produce explicit unsupported diagnostics.

Bounds are per tensor and operator allocation, not an operating-system allocator quota. Hosted arrays, JSON, IO, floating-point operations and training require the upstream hosted Lean runtime and host OS. They do not enter the worker image. The target uses disjoint checked scratch/output buffers, no heap, no floating point, no libc/libm/compiler-rt/libgcc/libuv/pthreads and no upstream Lean runtime. Its image links exactly the generated startup.o and genuinely elaborated/lowered program.o.

This is a small working numerical API and specialized differentiable operator subset. It is not a general tensor compiler, automatic differentiation of arbitrary Lean, or JAX/PyTorch/scikit-learn parity. No theorem of compiler correctness or learning-policy optimality is claimed.

Model, labels and permitted use

The two ordered features are recent independent error rate and normalized review gap. Both must be present, finite and in [-1,1]; ordinary fixture values are in [0,1]. A missing feature rejects with a fallback diagnostic. The explainable due/error review policy remains operational authority and fallback. A model result can propose a review or another permitted low-risk suggestion; it cannot certify mastery, change a checker result, grant access, disclose an assessment answer or promote itself.

The redistributable synthetic fixture labels risk by 0.1 + 0.6 × error rate + 0.3 × gap. Sixteen fitting rows and eight evaluation rows have fixed disjoint session groups and IDs before fitting. Evaluation times are separate from fitting times. No assisted practice supplies these synthetic independent-outcome labels. Unit scaling is fixed, so there are no fitted preprocessing statistics. Engineering reruns evaluate the same fixed held-out set; the fixed 160-update schedule and optimizer were not selected from those results, and there is no separate final test set. Synthetic outcomes establish pipeline behavior only; a smaller numerical error does not establish improved human learning. The linear score is an uncalibrated synthetic estimate, not a probability guarantee.

Training starts from zero parameters, uses batches of four in manifest order, half squared error, and momentum SGD with learning rate 0.1 and momentum 0.5. The reverse pass uses d(a+b)=(1,1), d(a×b)=(b,a), and d(½e²)=e. It returns parameter and input gradients. Independently derived checks use weights (2,-1), bias ½, features (½,¼), label ¾: prediction 5/4, loss 1/8, parameter gradient (¼,⅛,½), input gradient (1,-½), and first updated parameters (1.975,-1.0125,0.45). Central finite differences supplement these independent expected values.

Dataset and exact recovery

The manifest identifies source, CC0 synthetic-row grant, transformation source and digest, feature order, missingness, label origin, split grouping, ordering and exact train/evaluation byte digests. Actual row IDs, group membership, split and count must match the manifest. Duplicate record IDs, group overlap, undeclared trailing rows, malformed UTF-8, assisted labels and altered bytes reject. The Lean JSONL/JSON decoder consumes at most 512 bytes per read, admits rows of at most 2048 bytes, retains a four-row batch and limits manifests/checkpoints to 64 KiB and splits to 4096 records subject to that manifest bound. Hosted integrity hashing separately invokes sha256sum; its internal read buffer and RSS were not measured by the decoder receipt. The reported nonresident-dataset property describes the Lean decoder/batch path, with no claim about all upstream-runtime or checksum-process allocations. A 512-row fixture exceeds the worker's entire 16 KiB ordinary checked-region capacity while that decoder retains bounded chunks; it is not sent to the inference worker.

Each completed update atomically replaces a checkpoint containing schema, the exact Train/Linear/Tensor implementation digests, numerical/code versions, dataset digest, step, next record, epoch, RNG state (fixed one; no randomness is used), parameter bits, velocity bits, optimizer configuration and batch size. The complete recorded import/pin source inventory remains in the separate training receipt. Binary64 values are serialized by exact 64-bit patterns; decimal float display is not used to recover optimizer state. Resume checks nextRecord=(step×4) mod recordCount and epoch=(step×4)/recordCount, so an invalid cursor cannot silently skip or duplicate updates. A real SIGKILL between updates followed by resume is compared byte for byte with an uninterrupted complete run in the same pinned hosted binding. This is process-interruption/atomic-rename evidence, not cross-runtime bitwise portability, fsync, host-crash or power-loss durability.

Runtime wire and school authority

READY is LEMMA_SCHOOL/1\nREADY\n. A request has 16 bytes: LMQ8, version1, command, payload byte count, zero flags, UInt64 request ID. Command1 has exactly 72 payload bytes: generation, fence, model version, weight0, weight1, bias, feature0, feature1, presence mask. Command2 has no payload and requests clean exit. A session admits at most 64 requests. Scratch[0..87] stores request bytes; output[0..31] stages the response words. All access uses the preserved checked-memory operations; only the four closed UART operations perform device MMIO.

The 48-byte response has LMS8, version1, status, length32, zero flags, request ID, followed by generation, fence, model version and signed Q20 score. Malformed version/flags/magic return status14, wrong admitted command length status16, unknown command status17. Payload counts above72 terminate with status16 before payload access. Each UART poll is bounded by one million iterations. Oversized request rejection, empty/truncated receive timeout, budget exhaustion and process interruption are failures or explicit rejections, never ordinary inference success.

The worker echoes ownership metadata; it cannot decide whether a school lease is current. The durable school authority verifies school/job/worker/generation/fence, expiry, cancellation and artifact binding before committing a result. The runner retains raw request/response bytes, exact request ID, image hash, source-bound audit and execution receipt, and writes an origin:"rv64-observed" response artifact. Host-generated reference values appear only as an independent acceptance oracle. Uploaded observed bytes remain owner-local evidence within the documented development trust boundary; a JSON label is not cryptographic remote attestation.

Cancellation is enforced at the authority's result-admission boundary. The worker does not poll school state, read a lease clock or preempt an inference on cancellation; an owner can terminate its process, and command2 exits between requests. The adapter's 20-second response timeout and target polling bound are distinct from lease expiry. The recovery experiment writes an incomplete framed request to the real guest process and SIGKILLs it before a complete response. After reassignment, a separate real guest deliberately sends a response bearing the old lease; that observed stale response is rejected. The killed process is not claimed to have returned later.

Numerical leases also use the local provider registry. The actual runner declares one local node with four concurrent slots, 512 MiB aggregate configured guest RAM and a 256 MiB conservative concurrent CAS-closure reservation. Each registered worker declares one virtual CPU, 128 MiB guest RAM, 88 input bytes, 48 output bytes, 16384 checked-region bytes, the exact image digest and core0-v0.5/school-linear-worker/1 compatibility. The matching QEMU command configures -smp 1 -m 128M. These are declared admission envelopes and verified artifact availability, with no cgroup, filesystem free-space or physical availability guarantee.

Initial health is an authorized controller report of readiness to launch, distinct from observed VM readiness. Actual READY bytes stay in the execution streams; the four-worker workload additionally retains individual live READY observation receipts before its explicit paused barrier. A lease binds the configuration and exact health-report sequence. The runners leave that report unchanged during successful active work and refresh it after commit. Node/worker drain rejects new leases while permitting existing work to complete; an exact committed retry survives a later health refresh. The failure scenario reports offline only after the real SIGKILL, at controlled time101 before lease expiry110, and reconciles twice without duplicating rows before reassignment. No remote health attestation or multihost placement is claimed.

Audits, evidence and remaining work
