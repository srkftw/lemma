School operation and clock binding v1

Task009 extends the existing hosted Lean school authority. The domain model, scheduling, authorization, immutable records, restore decisions and transaction ordering remain in Lemma/School. Python transports bytes, holds the OS lock, supplies random pairing secrets and performs the narrow file/directory fsync primitive. This binding remains a single Linux host authority, with no replication or physical power-loss qualification.

Clock domains and compatibility

lemma-school-state/2 retains every historical record's sequence, timestamp and data. Version1 snapshots are read and explicitly migrated on opening; their previous raw-monotonic high-water mark becomes the logical scheduling base. An older binary rejects version2 rather than ignoring its new time interpretation. Snapshot/export envelopes retain their checksum and artifact-closure formats.

Historical ordering is the contiguous immutable sequence. Scheduling time is logical milliseconds. clockEpoch identifies the Linux boot, clockEpochSequence counts rebases, and clockAnchor/clockBase bind that boot's monotonic reading to logical time. Same-boot stopped time is measurable and counts. Across a different host or boot, downtime is unknown and the scheduling clock freezes at its last acknowledged base; future reviews therefore do not acquire an invented elapsed-time observation. Already-due work remains due. The next measured uptime advances the new scheduling clock. This conservative rule can delay a review after unmeasured downtime; it makes no retention claim.

Worker leases use an identified boot-relative leaseBootExpires, leaseClockEpoch, execution generation and increasing ownership fence. The legacy logical expires remains a display/compatibility field. Every authority start and clock-domain migration durably changes execution generation before admission. Restore begins a new generation. No old lease can revive after rebasing; reconciliation requeues within its original retry policy. Local bearer admission also binds the clock epoch sequence, so unmeasured downtime requires new pairing instead of extending a possibly expired credential. controlled-ms remains an explicit synthetic scheduling fixture, with its own supplied time and no claim of elapsed real time.

Selected storage contract

Before publishing a reference, Lean writes and hashes the bounded artifact, closes it, requests a file barrier, renames it, and barriers both destination and staging directories. Before acknowledging domain state, Lean validates its history and required immutable artifacts, writes a checksummed private snapshot, barriers that file, atomically renames it over state.json, and barriers the school directory and its parent. Export manifests and reusable package publication also receive file and parent-directory barriers. The selected school root's ancestor directory must already be on durable storage; the launcher does not certify unrelated directory creation or filesystem mounting.

scripts/school_fs_barrier.py opens only the Lean-selected regular file or directory without following its final symlink, invokes os.fsync, and fails on errors. It does not read school schemas, select commits, rename files or acknowledge work. Its exact source and copied payload enter the hosted production receipt. A barrier failure during a domain commit stops the cached authority; recovery must reopen and validate the authoritative snapshot before another mutation. This avoids continuing from uncertain cached state.

The stronger acknowledged-state guarantee is conditional on a local filesystem providing atomic same-filesystem rename and honoring successful file/directory barriers, and a storage stack/device honoring those barriers. Actual process interruption and injected barrier failures are executable checks. They do not establish host-crash recovery on every filesystem or physical power-loss behavior. Earlier close/rename observations are not retroactively promoted.

Bounded operation

The long-lived authority validates the snapshot and artifact closure once while holding the inherited OS mutex. It retains the validated Lean state, serves ordinary queries without rereading artifacts or rewriting snapshots as uptime advances, and verifies newly referenced artifacts before committing. A failed request leaves the cached state unchanged; a failed commit terminates admission. Explicit recovery/export still verifies the entire required closure. A malicious local filesystem owner is outside this owner-local binding.

Actual domain mutations still publish a bounded complete snapshot, and current projections are rebuilt from the admitted history. This removes the concrete read/recommit bottleneck without claiming a general indexed database engine. Record/artifact/queue/worker quotas remain enforced. Larger-history mutation costs, incremental journaling and independently measured host-crash/power-loss qualification remain separate obligations.

Local transport and lifecycle

run exposes the existing diagnostic owner endpoint at loopback /v1/command. run --client-port adds a separate loopback /v1/client endpoint in the same mutex-owning process. client-run exposes only the protected endpoint. That endpoint accepts a bounded JSON command and a Bearer secret, wraps it for Lean admission, and never exposes the diagnostic path. Lean derives the principal from the stored secret hash and evaluates its scoped grants. A caller's actor/school fields confer no authority. The protected operation allowlist excludes host-path operations; bounded work uploads convey bytes. This is local admission with OS-protected credentials, not internet TLS or production device-key protection.

start, status, stop, backup, restore, fork and pair are maintained transport conveniences over those same Lean commands. Runtime metadata binds PID, kernel start ticks and actual host boot ID; it is a diagnostic ownership record and grants no school authority. Pairing uses 32 OS-random bytes, writes a new private mode0600 credential with file and parent barriers, and sends only its SHA256 to Lean. Reusable forks get independent school/deployment identities and separate files, excluding learners, grants, credentials, observations and worker ownership. Operational restore preserves authorized history and requires the original authority to remain stopped.

Exact launch and recovery commands; focused executable recovery checks. Native/browser learner-device admission, remote encryption, general database scaling, physical and educational qualification require their own evidence.
