# Course-preserving Save1

`lemma-course-preserving-save-notebook-artifact/1` identifies Package notebook
cohort11 for the canonical and Clocked13 companion deployments. Hardware,
clocks, capacities, Surface-v2, Store protocols, durable formats, managed
language/runtime profiles and checkpoint serialization are unchanged.

An idle Package toolbar Save uses `packageRequestSave`. It preserves the open
course, selected package context, annotations and framebuffer outside the
durability footer. It uses the existing owned Store status request, operation8,
and the same phase6 completion validation. Request admission publishes Pending.
Only the unchanged validated completion pump can publish Saved. Save neither
installs a package nor changes a mathematical submission, goal or evidence.

The helper declines while a checker, raw buffer or Store call owns the shared
IPC slot, and preserves existing failed/read-only behavior. The ordinary
toolbar still cancels/consumes outstanding package/checker work before using
that slot. Companion recovery/reconciliation policy is unchanged. Preparation
and admission failures use the existing Failed path; no reply or successful
barrier is invented. A status request may acknowledge an already established
durable floor; it does not manufacture new persistence.

Previously, all Package toolbar actions called the old notebook toolbar,
which left the course and rebuilt the whole page before issuing Save. A real
source9 browser action exhausted its290s subrun at26.5M additional cycles with
no explicit Save receipt or new status scan. The native RTL reference
of that action exhausted the original absolute deadline; its60M-cycle action
ceiling was not extended. Retained diagnostic snapshots are prefixes,
not successful Saves. The earlier actual pointer stroke had independently
received its automatic durable Saved8 acknowledgment and exact native/Wasm
comparison; these are different observations.

Historical cohorts9 and10 keep their separate complete authorities. Cohort11
requires both genuine normal/initializer catalogs for each deployment and
complete pre/post LLVM body/global/caller pins. The common pre-body comparison
adds only `packageRequestSave` and changes only `packageToolbar`; all other
original bodies, arguments, effects and globals remain equal. Unknown catalogs,
partial or mixed cohorts, altered calls and altered complete corpora reject.

Literal Action checks reject course/package writes, framebuffer writes outside
the footer, overwritten busy work and fabricated Saved at admission. Genuine
checked User2 lowering and an RV64 object account for the sole syscall helper.
Whole-image audits and actual user/guest/controller acceptance remain separate
requirements. This contract alone establishes neither measured performance nor
browser cold recovery, exact fast timing/cache continuation, full mathematical
verification, digital-device completeness or physical panel qualification.
