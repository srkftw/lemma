Guest school submission envelope 1

The ordinary guest freezes one original mathematical workspace, packed ink index and all referenced original raw ink chunks. The transport copies its exact bytes. The maintained Lean decoder and admission resolve the original joined school binding, retain the immutable artifact and distinguish guest observations, hosted exact checking and human assessment. Neither five host-entered integers nor a latest UART reply supplies this submission.

All header fields are unsigned 64-bit little-endian words. The magic is 0x31425553534d454c, version 1, header length 256 bytes, maximum complete artifact 262144 bytes. Queue identity is 0x5351000000000000 | (captureStoreFrontier+1), with frontier below 0xffffffffffff. It is an immutable idempotency identity inside the original school binding; it is not a globally authenticated device identifier.

The payload is the complete original PackageWorkspace (including original Doc8, history and Known/Unknown execution identities), then the packed version-2 ink page, then raw version-1 ink chunks in original index-entry order. At most eight chunks are admitted by this bounded profile. Invisible chunks, index object/stroke identities, edit log and edit cursor remain present. Every referenced chunk header is validated against its original page/stroke; body length is exactly 128+72*sampleCount. Missing, duplicate-object, truncated, unreferenced or trailing data is rejected. The original raw sample bytes remain raw observations; structural acceptance does not authenticate sensor input or interpret handwriting.

The hosted decoder executes the actual read-only guest workspace/document validators under a finite interpreter. Typed work additionally requires an exact current package selection for the same course, edition, CRC, node, revision, goal, domain, assumptions and budget. The original guest result and execution contract remain separately recorded. Hosted exact checking applies only to supported typed fields. Opaque work is admitted for any published activity and has outcome Unsupported / human review even when the preserved document contains an earlier typed success. This retains resource-failed or unselected exact work without granting it exact-checking scope.

guest-submit accepts bounded lowercase hexadecimal bytes through the protected local principal transport. The server derives actor and school from verified local admission, resolves the original session record, checks current enrollment/session/generation/expiry and original publication policy/CRC, and stages the artifact before the referencing domain commit. The existing scoped teacher review and artifact operations expose that exact artifact beside its original prompt, sources, rubric and assistance/delivery records.

The idempotency key is the original binding record plus durable queue object. An exact already committed artifact returns its original attempt and commit sequence, including after the original session expires or is cancelled. Different bytes at that key are rejected. A caller still needs current principal admission to retrieve the acknowledgement. Fresh work under a revoked, replaced, expired or stale binding is rejected; it is never retargeted to a newer edition. An optional review identity is validated and frozen in the original JOIN invitation record, so submission transport cannot retarget a response to another review.

A successful school receipt contains attempt, queueObject, bindingRecord, artifact (SHA256), envelopeCRC32 (CRC32/ISO-HDLC, initial/final XOR ffffffff), original commitSequence, document revision, course, edition, policy, outcome and reused. The authority emits it only after its declared storage commit. CRC32 supports the guest receipt comparison; SHA256 remains the durable artifact identity. A transport end marker is not this acknowledgement.

Guest console stream tags are 0x72e start (queue object, metadata commit sequence, total bytes, namespace), 0x72f data (queue object, offset in low 48 bits plus valid byte count in bits 48–63, two little-endian words), and 0x730 end (queue object, metadata commit sequence, total bytes, status). The data count is 1–16; unused trailing bytes are zero. An assembler accepts only complete, ordered, contiguous bytes for one declared identity and length; interleaved unrelated tags carry no submission authority. Product capability tag 0x731 advertises this version. The maintained guest acknowledgement mailbox uses its separately versioned package command; a host cannot directly mutate the guest queue.

Structural fixture tests execute maintained Actions in bounded RAM and exercise admission faults. Actual guest/native/browser execution, transport framing, Save/reset recovery and receipt consumption require their own product scenario. Local bearer admission is not internet TLS, production device credentials, proof-kernel verification of handwriting, sensor qualification or demonstrated educational benefit.
