# Authored hint applicability, version 1

`lemma-authored-hint-visibility/1` changes the aligned arithmetic panel's
selection of an existing local authored proposal. It is application policy,
not a language extension, mathematical evidence, or a live tutor integration.

An aggregate historical assistance count does not authorize a current hint.
The guest reads the current document revision and goal and scans the bounded
version-1 learner event log. A visible proposal requires an event with exactly
that revision, goal, request kind 2 and local-provider value 1. Only the two
implemented local hint goals (rational addition and polynomial identity) have
proposals. A zero revision, absent matching event, unsupported goal, or unknown
legacy event version produces no current proposal. The historical assistance
count, all events, checked-result history and review estimate remain unchanged.
Namespace/page ownership and immutable package bindings remain enforced by the
existing document/reader caller before rendering.

The event version is at byte 208; the uncertainty marker at byte 200 is a
separate field and cannot select an event layout. The scan admits at most 64 sixteen-byte events at the existing document offset
832. A count above 64 returns error 235. Actual read errors propagate. The
filter reads owned virtual memory and performs no writes. Rendering obtains
the filter result before writing the framebuffer, so these failures publish
no partial panel. The current proposal is recomputed on each render; editing
or changing a goal cannot reuse a proposal from another submission. Historical
events remain available for assistance accounting and review.

The genuine Lean declarations are `Lemma.Courses.HintVisibility.current` and
its bounded event callback. `ArithmeticAligned.render` supplies the selected
visibility to the existing character/span renderer. Its scalar font, aligned
word writes, geometry fallback and bounded frame extent are preserved. The
qualified canonical panel is 1650 by 2200 Gray4; historical alternate-geometry
fallback behavior is not newly qualified by this change.

`lemma-authored-hint-artifact/1` admits exact additive User2 artifacts through
the existing deployment validators. It retains immutable predecessor authority
files, exact configuration/root/ABI/effect checks, all unrelated authority
fields and complete pre/post LLVM body/global/caller pins. Every admitted
deployment adds exactly the two read-only helper declarations. Compilation,
artifact audits, CPU execution, persistence, and browser execution have
separate observed results; the existence of pins is not an execution result.
