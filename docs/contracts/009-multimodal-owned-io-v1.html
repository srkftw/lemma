Owned multimodal record and PCM interface v1

This additive software interface is syscall69 service version2 (operation18). Converter hardware discovery remains version1. Legacy operations0–11 retain their meanings. It applies to the existing modeled converter in functional0.14 and canonical0.15; it does not add image frames, a physical ADC/DAC, link bandwidth or a new machine-description framework. A matched guest/kernel source closure is required. Older guest/kernel pairs remain separate maintained artifacts.

The existing named endpoint capability remains mandatory for every operation. Acquisition, local processing and playback grants retain their independent purpose, epoch, expiry and resource checks. No caller supplies an MMIO or physical DMA address. The implementation is ordinary Lean kernel policy, consumed by the Notebook acquisition client.

There is one global pending record. Its logical caller identity and kernel frame survive ordinary machine state; user mappings are resolved afresh at completion. A retired client's completed/cancelled transfer can be reclaimed by a later grant. A valid unconsumed transfer remains owned, and an outstanding controller write always prevents reuse. Kernel metadata copies use a separate page. The single-hart, nonpreemptible syscall boundary remains an explicit assumption; no user physical alias survives a call.

The notebook fairly starts at most one record and polls completion without busy waiting, including cleanup after acquisition stops. Samples stay transient. No transmit, retention, research or training authority follows from acquisition. The five-second synthetic CAPTURE and sensor-refusing default remain unchanged. Supported PCM helpers let an application explicitly grant output, prefill arbitrary bounded samples and start; they do not grant a tutor output authority.

Explicit local output consumer

The notebook's AUDIO TEST control atx1120–1264/y132–160 consumes this interface. It follows ordered ink/control admission; it cannot replace pending work. The actual User client lazily allocates its own page at0x360000, obtains only local output purpose64, and arms a16kHz/6250-tick controller with128 budget bytes. It prefills sixteen arbitrary S16_LE samples before starting. This is a one-millisecond digital fragment and maintenance operation, not speech, a continuous stream, physical audibility or a latency qualification. It does not enable acquisition, transmission, retention or training.

Record715 binds the test sequence, output epoch, accepted16 samples and period. Record716 binds that sequence, accepted prefix, last independently observed consumed prefix and terminal reason:0 all intended samples consumed,1 explicit local inhibition,2 expiry,3 error,4 superseded grant. A queued packet is not a consumed receipt. Counter overflow rejects before enqueue. A stale background completion never revokes a later grant or attributes its counter to the old packet; explicit MUTE still inhibits current local output. Repeated pumps cannot produce duplicate completion receipts. Physical/speaker presentation and assistance exposure retain separate authorities.

The current16-entry FIFO and software polling do not establish continuous playback or an underrun-free end boundary. A later empty deadline can latch the controller's existing underrun fault before the User pump stops it; a consumed-prefix receipt does not assert the absence of that fault. Continuous PCM requires an owned controller buffer/ring and its exact continuation and refill/stop semantics. Ordinary notebook Save and sensor-refusing operation remain available.

Qualification is in progress. Focused hosted Actions and source negatives exercise ownership, changed mappings, expiry, partial PCM acceptance and cleanup. These are separate from compiled guest/controller execution, in-flight checkpoint admission, presentation, performance and physical qualification. The64-byte converter record remains a scalar/event aperture: full image frames, wavelength schedules and other adopted raw representations remain unfinished. No3,902,720B/s economy or full-raw link claim follows from this interface.
