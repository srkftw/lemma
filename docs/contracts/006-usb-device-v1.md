# USB decoded-packet device v1

`lemma_usb_device.sv` implements a bounded full-speed development device at a decoded packet boundary. Packet bytes include PID, token CRC5 and DATA CRC16. SYNC/EOP, NRZI, bit stuffing, line sampling, electrical behavior and complete USB conformance remain unimplemented. The reference is the [USB-IF USB 2.0 specification](https://www.usb.org/document-library/usb-20-specification), base PDF SHA256 `d39698a33486c399124af92bd02e4f978fd9a836b5cf4e52e6e4633eb1d89f61`. No allocated VID/PID or USB certification is claimed.

The device has EP0 control, bulk IN1 and bulk OUT2, maximum 64-byte copied payloads, one immutable IN slot and one retained OUT head per admitted endpoint. Raw input supplies connected/reset and actual packet bytes; raw output supplies actual generated packet bytes. Host transport cannot set addressed/configured state. CRC-invalid packets cannot publish an OUT head or generate a successful handshake. Matching duplicate OUT packets are acknowledged without republication; a new packet facing a retained head receives NAK. IN retransmission retains the identical payload, PID and CRC until a real ACK advances its toggle. STALL, CLEARHALT, cancellation, disconnection and qualified bus reset have explicit circuit transitions.

Address and configuration writes are proposals validated against the actual retained SETUP. They become effective only after the corresponding zero-length DATA1 status packet receives a real ACK. New SETUP aborts earlier EP0 work. A generation register and explicit expected-generation binding prevent a stale guest response or destructive POP from applying to a later SETUP. Generation exhaustion fails closed until full reset. A bus-reset input qualifies at 1,000,000 declared 100 MHz clocks (10 ms); the hosted root-port policy requests 5,000,000 clocks (50 ms). Neither count models voltage or a physical USB PHY.

PIO registers are aligned 64-bit words: magic/version 0/8; status/address/configuration 16/24/32; W1C events/fault/command 40/48/56; IN lengths 64/72; OUT metadata 80/88; address/configuration proposals 96/104; RX/TX/reset counters and ticks 112/120/128/136; pending proposals and toggles/halt 144/152; SETUP generation/expected generation 160/168. Commands are ARM_IN=1, POP_OUT=2, HALT=3, CLEARHALT=4, CANCEL=5 with endpoint in bits8..15. EP0/IN1 packed staging begins at0x100/0x140; EP0/OUT2 retained packed heads at0x200/0x240. Invalid ownership/offset handling belongs to the Lean driver; this PIO controller performs no DMA.

The intended optional hardware successor is0.6: USB aperture0x10010a00/0x400, IRQ16, Binding6/descriptor ABI7. SoC decoding must subtract the actual base; this base is not aligned to1024 bytes. Existing0.3/0.4/0.5 bindings remain unchanged. Integration and actual RV64/Store acceptance remain separate from this leaf result.

`python3 scripts/check_usb_device.py --work-dir UNUSED_BUILD_PATH --jobs 2` builds the actual circuit with pinned Verilator and compares arbitrary partial-RX and pending-status-ACK generated-state suffixes. The independent CRC oracle uses an MSB polynomial formulation; the circuit uses its reflected formulation. The checked result is a literal circuit qualification, not guest execution, durable companion storage, machine checkpoint closure or full USB support.

Hosted opaque backing policy is extracted unchanged into `sim/companion/ClientPolicy.lean`; the normal companion build accounts for its generated host objects and links it only into the host client. Host runtimes and objects never enter RV64 images. Existing peer barrier/receipt/outbox rules are retained. The prepared peer checks remain separately scoped opaque transport tests.
