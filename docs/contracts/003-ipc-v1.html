Bounded capability IPC v1

This is the Gate I lower-layer construction contract. It defines the interfaces to implement after the Gate H checkpoint; it asserts no compilation, audit or runtime pass. Shared Lemma.User.IPCABI defines calls20 Send,21 Receive, 22 asynchronous CallBegin,23 CallWait,24 Reply and25 Cancel. Public errors are wouldBlock12, queueFull92, timeout93, canceled94, peerDied96, invalidTransaction97, bufferTooSmall98, inFlight99, alreadyCompleted100 and invalidPacket101. Capability errors remain unchanged. Internal blocking254 never reaches User;255 denotes a kernel invariant failure.

Ownership and dependency order

IPCStorage imports Memory.AddressSpace, Memory.UserCopy and pure numeric User.IPCABI declarations. It stores checked transactions and copied packets, but neither grants capabilities nor selects or resumes tasks. Objects may import IPCStorage; Capability imports Objects and uses storage cancellation before retiring object authority. Kernel.IPC imports Capability, Objects and IPCStorage, with no Task or Process import. Task and Scheduler integrate blocking and checked saved-context completion above Process. There is no lower-layer callback into the scheduler.

Descriptor frames are allocated and resolved as owner1/purpose1. They already meet UserCopy's kernel-scratch requirement, so IPC allocates no global packet frame or per-call scratch frame. The empty managed baseline remains498 frames: one task-table frame and one global object-table frame in addition to the stable kernel address space. Each Endpoint retains its real one-frame queue.

Descriptor transaction storage

Every checked descriptor reserves128 bytes at offsets3648..3775 for16 little endian UInt64 words and256 copied packet bytes at3776..4031. The final64 bytes remain reserved. Capability entries end at3648 and do not overlap these fields. The metadata layout is:

There is at most one transaction per descriptor. The transaction serial is monotonic1..2^60-1; its next value can become 2^60 to represent exhaustion, and never wraps. A recoverable rejected preparation or publication does not consume a serial. Descriptor generation, transaction serial and full object key must all agree before changing a transaction. Reusing a registry slot is not sufficient identity.

The reserved state belongs to one bounded nonpreemptible transition. Preparation validates authority in Kernel.IPC and the complete required User range before copy or externally visible publication. Staged request bytes are kernel-owned. No borrowed physical User address persists. A stored User virtual address remains untrusted: completion validates the live descriptor and current complete mapping/permissions again. Empty payloads still require descriptor, object and transaction checks because UserCopy intentionally skips range/scratch checks for zero length.

A ready result is already committed. Cancellation, timeout, endpoint destruction or Reply destruction cannot overwrite it. The scheduler consumes it once through the exact transaction, updates a checked saved User context and resets storage to idle. Reset preserves the next transaction serial and withdraws bindings before clearing bytes. Descriptor detach clears pending authority before Capability.unregister and Loader teardown.

All parameters below are UInt64, and all functions return Core0 Action. Internal addresses returned by inspection functions are never User syscall results.

CallBegin immediately enqueues and returns its transaction, or returns queueFull92 before preparing storage, creating a Reply, changing references or consuming any serial. Phase0 is a provisional Reply inside one bounded nonpreemptible transition only; it is never retained for polling. An unexpected full queue after checked preflight is an invariant failure. CallWait binds the output buffer to the already queued transaction and may block awaiting its Reply. Blocking Receive mode1 owns a deadline; the initial ABI has no blocking Send or hidden CallBegin retry. Reply phases distinguish provisional0, queued1 and delivered2. No second Call can replace an outstanding transaction.

Kernel.IPC owns the ordering of preparation, copied-byte staging, object/cap preflight, queue publication and immediate-result reset. A committed queued nonblocking Send can reset its caller row; the copied queue record independently retains full sender and transaction identity. No unbounded Action recursion or dynamic callback is introduced.

Capability inspection call19 field5 requires the calling task's scoped Management/Inspect authority, a valid local Endpoint subject and the active boot-selected peer. It returns only whether that peer's checked storage row is waiting on Receive for the exact Endpoint. It returns no pointer, object key or authority. Existing fields0..3 retain their meanings; field4 and unknown fields are invalid arguments.

Four copied queue packets

An Endpoint queue resolves from its live object as an owner1/purpose1 frame. Its 128-byte header contains magic 0x31455551414d454c, version1, full Endpoint key, live count0..4, next FIFO serial, then zero reserved words. Four slots begin at offset128, have stride320 and end at1408. Each slot has64 internal metadata bytes followed by a maximum256-byte wire packet. The wire packet reserves64 bytes for its User ABI header and192 for application payload; Kernel.IPC validates and stamps that header. Its eight words are magic 0x31504349414d454c, kind Send1/Call2/Reply3, full authenticated sender descriptor, User request identifier, receiver-local Reply handle or0, payload length, application status (0 on requests; at most255 on Replies), and reserved0. Storage never obtains authority from header integers. User requests supply only payload bytes; kernel stamping cannot be replaced by a User-authored header.

The eight internal words are state0/free or1/live or2/reserved, FIFO serial, full sender descriptor, sender transaction, full Reply key or0, actual copied packet length, reserved0, reserved0. FIFO serials do not wrap; a new queue can start at1 only with a new full object generation. Selection scans four slots and chooses the least live FIFO serial. Queue validation checks actual count, slot states and bounded lengths rather than trusting only the header.

Unknown handles, malformed metadata, oversize packets and unexpected states fail closed. Queue-full and output-range/cap-table failures leave the queue, source authority, references and serials unchanged. Capacity and serial preflight precede frame/object/cap effects. After checked preflight, impossible metadata write failures are kernel invariants, not ordinary rollback claims.

Reply objects and authority withdrawal

The closed object set gains Reply type5. Its type-specific right/mask is1; this reuses an existing known rights bit and does not change knownRights=2047. Reply has neither Duplicate nor Transfer authority. Console's bit1 remains Read and cannot authorize a Reply operation because object typing is checked first. The accepted rights-mask table becomes [35,124,928,1056,1]; the compiler artifact audit must account for the actual new immutable table at the selected I roots. This is an additive shared capability/IPC ABI extension, not a new Core0 feature. Current H and I builds use the five-value mask; retained historical H builds with the four-value mask are not relabeled as outputs of this change.

There are at most four live/revoking Endpoints, eight live/revoking Replies and16 global objects. These are independent bounds. A Reply occupies one existing 128-byte object row and owns no frame. It binds full caller descriptor, transaction, Endpoint generation, deadline and, after delivery, full server descriptor. It has one explicit kernel pending reference and at most one server capability reference, so its reference count is at most2. It is not a pinned boot object. Endpoint waits add no hidden Endpoint references.

Objects supplies capacity preflight replyAvailable(), endpointQueue(endpointKey), createReply(callerDescriptor, endpointKey, transaction, deadline), replyFields(replyKey), markReplyQueued(replyKey), deliverReply(replyKey, serverDescriptor), beginReplyRevoke(replyKey) and destroyReply(replyKey). Existing registryDescriptor(index) and registrySlot(descriptor) bound enrollment. The Reply row's common owner word40 is the caller, word56 the Endpoint key, word64 the transaction, word72 the server (0 before delivery), word80 the phase 0/1/2, and word88 the deadline. Payload32 and pin48 remain0. Capability supplies grantReply(serverDescriptor, replyKey), retireReply(replyKey, status), cancelEndpointReplies(endpointKey,status) and cancelDescriptorReplies(descriptor,status). Destination entry and serial availability are checked before delivery publication. A reply attempt validates local type/right, object generation, server identity, live caller transaction, deadline and both current User ranges before consuming authority. A valid reply commits copied bytes once; a malformed range leaves live reply authority available for a defined retry. A stale, already used or cancelled Reply grants no authority.

retireReply first withdraws Reply authority, cancels its exact queued Call and completes its matching caller row unless already ready. It sweeps at most8 tables of16 entries to remove the server capability, drops the one pending kernel reference and destroys only at refs0. Generation advancement/retirement follows withdrawal. Leaving a dead object behind a live uncloseable capability entry is not acceptable cleanup. Closing a server Reply handle invokes this cancellation path rather than merely decrementing a reference.

Endpoint revoke, owner detach and last-alias Endpoint close retire matching Replies before dropping the final Endpoint reference or releasing its queue. User revoke remains Endpoint/Revoke only. Objects' queue destruction checks that no matching live Replies remain, invalidates matching descriptor waits across the checked8-entry registry, then releases the queue once. Objects cannot call Capability: the bounded Reply capability sweep is performed by the higher Capability layer before Objects destruction.

Timeout, caller/server death and endpoint revocation have defined public results and exactly one completion. Detach removes all messages of the dead full sender, including ordinary Sends, and all of its call/reply bindings. No ready result is overwritten, no registered dead descriptor can survive frame reuse, and no reply generation or FIFO/transaction counter wraps. Task/Scheduler wakes blocked contexts only after these lower transitions produce a checked ready result.

Enqueue linearizes when its copied slot becomes live; its fields, actual count and next FIFO serial are initialized first. Dequeue linearizes at withdrawal of the exact inspected FIFO slot, after checked copying and Reply-cap publication. Reply linearizes when the caller metadata becomes ready, after copying into kernel-owned scratch and a fresh hardware time sample immediately before commit. A deadline reached at that sample yields timeout, not reply success. Cancellation and timeout linearize at that same ready-state publication with their error. Later events cannot overwrite ready state or its packet. Capability withdrawal and bounded cleanup follow the commit before returning from the nonpreemptible transition. A timeout may follow server acceptance of a request; at-most-once completion does not assert exactly-once application execution.

Required evidence

The ipc-development boot policy links Server, ClientA, ClientB, Busy and one later-created Fault image separately. It prepares the first four before creating three Endpoint queues: primary owned by Server, private probe owned by ClientA, and inbox owned by ClientB. Grant order is Server Console34/primary8; ClientA Console34/primary20/probe124/Management928/inbox4; ClientB Console34/primary20/inbox8; Busy none. Management is scoped to ClientB. Each creation records actual owner/key/remaining frames before grants, and each grant records its actual local handle. Activation follows all grants. Ordinary construction failure aborts provisional tasks and their owned queues.

Checked Objects table word160 retains only the full primary generation key. Late Fault creation revalidates its type and live active owner task before any allocation, then grants Console34 and primary20 to the constructing instance. No raw physical pointer, arbitrary object authority, descriptor alias or generation mutation is exposed by this policy. The historical launch transport still requires its fourth payload word0; the IPC entry's explicit wrapper accepts four independently supplied launch nonces in the same forty-byte packet.

CapabilityModel proves that Reply's mask uses a known bit, excludes Duplicate, and leaves bit2048 unknown. These numeric facts do not establish storage integrity, at-most-once completion or linked-code correctness.

Genuine Lean compilation, immutable compiler/source realization, exact closed module/LLVM/object provenance, stack limits and bounded copies precede guests. Fresh O0/O2 sessions must separately observe two clients and a server exchanging independently chosen payloads, copied-packet sender binding, queue-full/empty behavior, timeouts, invalid-memory no-publication, denied Send/Receive, caller and server death, revoke while blocked, cancellation, duplicate Replies, complete local/object/frame cleanup and sustained unrelated-task progress. Host models and malformed-evidence tests do not substitute for those observations. No Gate I pass follows from this contract or the existence of source files.
