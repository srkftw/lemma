# Local native distribution1

`lemma-local-native-distribution/1` packages an existing admitted canonical
`lemmasim-native-bundle/2` or `/3`, its exact original compiled source archive,
and the maintained host command surface. It changes no RV64 image, ROM,
controller, profile, backend or lowering contract. Linux x86-64, Python3.10+
and the inventoried Nix loader/library paths are required; Tk is optional.
ELF preload remains development boot. Project redistribution permission and
complete product installation remain unresolved.

The root `run.py` verifies every inventoried regular file and byte count before
importing packaged code. Missing, changed, unlisted, symlinked or traversing
files reject. The original bundle is immutable. Mutable sessions, media and
derived bundle views stay outside the package. No installer, download or host
trust change runs implicitly.

The relocation helper adds only exact archived source-location aliases under
the extracted host root. An alias must select an already inventoried digest
from an original absolute path with the same relative source suffix. All
original origins and every non-location manifest field survive unchanged.
Both backends and both notebook/initializer roles then pass the existing full
admission. This does not reinterpret a failed guest audit or state identity.

Session/init retains its derived `.bundle` and `.bundle.relocation.json`
beside the session or initialization medium. The original command front end
implements session controls, raw input, snapshots, restore/replay and course
commands. A prepared launch needs no checkout or build helper. Explicit
development guest overrides can still require their original source/build
environment; their checkpoint identity is not silently removed for portability.
Product ROM/authentication/update and optional companion/radio adapters are
not included by this distribution version.

Without an explicit initialization log directory, `init --disk PATH` uses
`PATH.initialize` outside the package. Session/init subcommand help forwards
without creating a view or requiring a mutable path. A successful ordinary
initialization leaves every packaged file unchanged; formatting still occurs
through the actual separately audited guest initializer and backing barrier.

Optional `--include-nix-runtime` exports the existing Nix requisites of both
backend host-library inventories **and the actual QEMU runtime output**. The
earlier loader-only algorithm missed the program and runtime data invoked by
a compiled `makeCWrapper` launcher. Current packaging checks the copied
launcher and derivation bytes, queries the hash-matched original derivation,
selects its unique output containing that exact launcher, and includes the
whole registered output closure. Unused debug outputs need not be realised.
Each dependency is checked before export. Bounds:256 store paths,512MiB
source/export,30s output query,60s requisite query,180s export;
the child export has a file-size limit. The manifest records the export bytes,
roots, full requisites, dependency hashes and actual tool identity. Nix's
multicall invocation name is preserved. On a compatible Nix host, explicit
`nix-store --import < runtime-closure.nar` restores the original store paths
under normal host permissions. This is not a universal executable installer.
The included runtime never enters the RV64 link.

The complete package is bounded to8192 files/2GiB. Optional tar/gzip uses
relative regular files and fixed archive metadata. Original notices remain;
the local archive grants no new license. Existing LGPL/GPL and other upstream
obligations and unresolved project rights still constrain redistribution.

Qualification distinguishes four-way artifact admission, actual extracted
RTL transport, private offline runtime import, and exact same-backend suffix
execution. Both restored suffix branches can share a checkpoint omission;
their equality does not close arbitrary-boundary continuation. No package
preparation result establishes cold Ready, mathematical correctness, fast
timing parity, new-host installation or physical conformance.

The Linux visibility checker at
`conformance/lemmasim/check_native_runtime_closure.py` uses private user/mount
namespaces to expose only the named runtime store paths. It preserves the
original read-only mount protections, removes its source-store alias, and
compares actual old-inventory and complete-runtime launches. The positive RTL
probe loads the unchanged audited guest/ROM/DTB/descriptor and executes one
million clocks with actual retirement. This bounded runtime-linkage observation
does not qualify notebook Ready or cold recovery. The checker uses existing
listed store contents; it does not import a NAR or establish fresh-host
installation, Python/Tk closure or redistribution permission. Missing namespace
support fails, with no skip-to-success path or host-setting change.


`lemma-local-native-distribution/2` adds the ordinary dual-backend course
command wrapper and its fast UART adapter to the immutable inventory. The
packaged `run.py course-install|course-load|course-delete-probe` commands use
that wrapper only for version2. Version1 archives retain their original
command dispatch; the current verifier accepts both versions and requires
the extra wrapper files only for version2. The selected backend must expose
its admitted transport; packaging never manufactures controller readiness
or a guest receipt. Raw UART1 follows its separately versioned contract.

A version2 archive containing the unchanged genuine dirty-batch9 guest pair
and opt-in raw-UART fast machine has passed extracted Python-I initialization,
nonempty pending-input continuation, actual guest installation, independent
cold recovery and course load from /tmp. A separately built final version2
archive passed installation/load from the retained pending-input cut. The
first prototype archive retained a version1 label and is recorded separately;
it is not relabeled as version2. These observations qualify the specified
functional path, not general QEMU cached-state continuation or fast timing.
