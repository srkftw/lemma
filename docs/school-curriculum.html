School source ingestion and unit authoring

The hosted Lean curriculum implementation imports a JSON array of source strings, retains its exact bytes, and compiles one supported semantic unit definition into the existing lemma-course-package/1 bytes consumed by the guest reader. Hosted authoring uses the pinned upstream Lean runtime. It neither expands the freestanding language profile nor substitutes for guest installation, display or learner-record recovery.

An immutable revision lives at ROOT/catalogues/KEY/SHA256/. Its source.json is the exact input byte sequence; records.jsonl retains every original string, zero-based source position, original leading numeric label, original UTF-8 digest and validation result. The manifest binds source digest, exact source byte count, record artifact digest, record count, importer version, original filename and declared rights. Duplicate strings remain distinct records. A stable record identity is sha256:SOURCE_DIGEST#POSITION. Re-importing identical bytes validates and reuses the same revision; changed bytes publish a distinct immutable directory.

Strict incremental parsing admits only a nonempty JSON array of strings. The decoder rejects invalid UTF-8/escapes, non-string rows, trailing commas/data, truncated arrays and budget excess. Parsing uses a 64 KiB read chunk and at most 65,536 encoded bytes per token; the source limit is 512 MiB and the row limit is 1,000,000. Search is a bounded-memory scan with case-normalized comparisons, an explicit offset, and 1–100 returned records; original text remains unchanged. Search and lookup validate artifact digests and row order before returning. There is no compulsory preprocessing, embedding or model call. These bounds are admission budgets, not a claimed throughput result.

A staging directory is private until a complete parse and manifest are renamed into place. Ordinary failed imports remove their own staging directories; process-crash orphan staging cleanup remains an operator storage obligation. Atomic rename and close establish the stated local process-restart binding, not power-loss durability or authenticated provenance. Content hashes detect changed bytes, not malicious replacement of both content and its unsigned manifest.

SourceRegistry.Source separates bibliographic identity, edition, identity-verification evidence, file digest, owner-controlled location and rights. An Anchor records source/edition/digest, zero-based PDF page index where applicable, printed page label when known, section/exercise locator, verified/ambiguous/OCR/unavailable status and extraction lineage. PDF page indices are not printed page labels. Explicit resolve-sources checks available bytes; absent sources produce MissingSource, and differing bytes produce SourceIdentityMismatch. Compilation itself grants no filesystem/network effects.

Reference fixture and checking boundary

FixtureUnit.unit is an eight-stage sequence about distributivity and the cross terms in a square: prerequisite preparation, a worked four-product example, definition reconstruction, exact coefficient submission, analysis of a dropped-term argument, an independent proof, transfer to unequal constants and delayed reconstruction. The Lean theorem FixtureUnit.square_successor proves (x+1)*(x+1)=x*x+2*x+1 for every natural number by checked distributivity. The checked axiom inventory is the standard Lean propext; no new axiom is introduced. It is a reference proof, not a checker for handwritten student arguments.

The routine task uses the existing exact polynomial checker over Q[x]; varying coefficients produce Verified or Invalid in that precisely declared domain. Definition, invalid-argument explanation, independent proof, transfer and review reasoning require teacher review. Independent proof and review have no permitted tutor context or public worked answer. Authoring.tutorContext returns only admitted activity text/hints and excludes assessment criteria/reference theorem identifiers. The school authority separately enforces enrollment, grants, versions and assistance provenance. Software scheduling does not establish retention or educational benefit.

Observation metadata and separate consent

Lemma.School.Observation supplies pure, versioned observation metadata and admission for school use. Each observation retains modality, schema, school/learner/source identities, acquisition time and clock, calibration/quality metadata, measured/derived/synthetic origin, and optional parent-observation lineage. Present data requires an immutable artifact digest; missing data has an explicit reason and no measurement bytes. It cannot silently become a zero reading. The metadata model does not activate a sensor or interpret its payload.

Acquisition identity is distinct from execution identity. Observation.replay preserves the original identity, acquisition timestamps/clock, origin, source and artifact while recording a new execution identity, replay clock and replay time. A synthetic observation remains synthetic during live delivery and replay. Root authority must resolve the original durable record and same-school/learner lineage; replay does not create a new learner performance result.

Versioned Consent grants separately admit collection, processing, upload, retention, training and export for an exact school, learner and observation/source resource. Callers obtain the latest durable consent; revocation affects subsequent eligibility. eligibleForTraining requires present data and current training, processing and retention permissions. Retention revocation blocks new retention/replay and dataset eligibility. Processing and export of already retained data follow their separately granted permissions; revoke those permissions separately when needed. Original bytes remain pinned in immutable history. Physical purge and previously trained model removal are unsupported. This is an eligibility hook, not an implemented private-data training loader or deletion/unlearning guarantee. The release training workload remains an explicitly identified synthetic fixture. Production identity and sensor transport require their own gates.
