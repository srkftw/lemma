Owner-local companion, checking and assessment

This implementation extends the maintained Lean workbook. The companion proposes assistance; the existing guest installer, Store, copied-action gate and paper controller decide what is installed and presented. A model response, an installed package, a successful rasterization and a completed panel update are separate observations. The companion never grants mathematical verification.

The native scenario declares its virtual and wall limits before launch, uses private disk copies and public device/session controls, and retains its original failures. Its intended observations include original-course installation, actual model inference, guest paper pixels, seven fresh isolated checking requests, local capture/revocation/mute, pen input and Save, and independent cold recovery. A command or harness alone is not an execution receipt.

Cryptographic components and live-session boundary

The target Lean implementations cover ChaCha20, Poly1305, IETF ChaCha20-Poly1305 and a bounded 32-byte SHA-256 HKDF expansion. Independent published vectors come from RFC 8439 and RFC 5869. The RV64 component checker genuinely elaborates, lowers through LLVM, audits and executes the target vector workload. Known-answer and tamper tests do not establish side-channel resistance or production qualification.

The host protected-session reference implements transcript-bound directional keys, authenticated framing, packet and stream sequences, bounded priorities, consent-aware queued cancellation, reconnect and nonce exhaustion. The scalar target session policy and target cryptography are not yet integrated into a protected live companion channel. Owner provisioning, live entropy, physical entropy hardware, snapshot-safe key management and production identity remain separately unqualified. Simulator entropy and deterministic development keys cannot authorize physical private-data collection. The older CRC64 opaque storage protocol keeps its independent durability meaning.

Remaining boundaries

The default guest flow is text-only, with visible unverified assistance. It does not claim guest PCM tutor playback, measured audibility, general speech accuracy, physiological interpretation, raw camera/ToF/photon-flow acquisition qualification, real-time consumer performance, arbitrary checkpoint exactness or educational benefit. The assessment pipeline requires actual independent learner submissions and controlled comparisons before any human benefit claim. No human recordings or body-connected activation are authorized by this software work.
