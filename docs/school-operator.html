Lemma documentation

Run and develop a local Lemma school

Foundation 0.1.0 runs one school authority on the owner's machine. School decisions, authorization, authoring, training and recovery are maintained Lean. The authority is a hosted native Lean program using the upstream host runtime. Its separately audited inference worker is freestanding RV64. No remote account, model API or paid service is required.

Use the native LemmaSim school workspace to switch between Study, Teach, Operate and Develop. It presents the same commands below and delegates drawing, course installation, joining and visible assistance to the actual guest device path. With a private pairing credential, Lean derives the principal and applies scoped grants. The separate operator-local filesystem and diagnostic endpoint still trusts its OS caller. This is a local admission binding, not a public authenticated internet service.

Initialize, run and restart

Task009 adds explicit clock epochs and storage barriers, cached read-only queries, protected local pairing, and ordinary lifecycle commands. Historical Task008 evidence retains its original close/rename and same-clock scope.

From the repository root, choose a fresh ignored directory. The launcher builds with the pinned environment and takes the school's OS mutex. The owner can grant specific action/resource capabilities to another identity. Protected enrollment requires an explicit enroll/school grant; learners can inspect their own work through verified admission. Attempt, observation and client-session identifiers are currently school-wide: use unique identifiers for separate learners and submissions; reusing one for different work fails with an idempotency conflict.

scripts/lemma-school build/school/my-school '{"op":"init","school":"my-school","actor":"owner","deployment":"local-a","provider":"local"}'
scripts/lemma-school build/school/my-school '{"op":"status","school":"my-school","actor":"owner"}'
scripts/lemma-school build/school/my-school run --port 8790

The last command exposes only http://127.0.0.1:8790/v1/command. The supported transport is bounded JSON over loopback HTTP or serialized local commands. A second writer fails the OS lock. The native child inherits that lock, so abrupt transport-parent termination cannot admit a competing writer while the child is still committing. Stop through the panel or an HTTP stop command; restart with the same run command. Each long-lived authority start commits a new execution generation before accepting work. Raw .lake/build/bin/school is an internal serial binding; public callers use the mutex launcher/transport.

Default budgets are 10,000 records, 8 MiB per artifact, 32 outstanding jobs with four queue slots reserved for interactive work, four leased workers, three retries and 60-second maximum leases. Supply a complete budgets object at initialization to change admitted limits; Lemma/School/Model.lean and Store.validBudgets define exact fields and hard caps. Only the local provider is implemented; unsupported providers fail. Status reports identity, generation, budgets, jobs and committed artifact closure. Reconciliation requeues expired or prior-generation leases within the retry budget and cancels exhausted jobs; repeating it without new failures does not duplicate work.

The native authority launcher defaults to two Lean workers and a 64 MiB worker-stack setting; explicit LEAN_NUM_THREADS and LEAN_STACK_SIZE_KB overrides remain supported. The native entry thread and allocator each reserve about 1 GiB before ordinary work, so a finite virtual-address limit must allow at least 4 GiB. The launcher diagnoses a smaller inherited limit before spawning Lean; it never raises the operator's limit. Virtual-address reservations are separate from resident memory. The Task009 restore test used a 4 GiB address cap and measured its resident use separately; its earlier 2 GiB startup failures remain retained.

Ordinary lifecycle and local pairing

Use separate loopback ports for owner-local administration and protected learner/teacher admission. The owner endpoint trusts the local OS caller and must remain private. The protected endpoint derives the principal from a private pairing credential, then applies Lean grants; changing an actor field or opening a different activity grants nothing. These commands require the actual school and owner identities. The token file is mode0600; its secret is never printed.

A teacher acting as school administrator can invite or revoke a principal after receiving the explicit admin/school grant, and enroll learners after receiving enroll/school. The existing admission operations run through the protected endpoint; no operator identity or host-path operation is exposed. The pairing command reads an owned mode0600 regular credential, creates a separate mode0600 handoff containing32 OS-random bytes, barriers the file and directory, and sends only the new token hash to Lean. A failed admission leaves a visibly unadmitted handoff file; it grants no access.

scripts/lemma-school build/school/my-school '{"op":"grant","school":"my-school","actor":"owner","subject":"teacher","action":"admin","resource":"school"}'
scripts/lemma-school build/school/my-school '{"op":"grant","school":"my-school","actor":"owner","subject":"teacher","action":"enroll","resource":"school"}'
scripts/lemma-school build/school/my-school pair --credential teacher.json --learner second-learner --to second-learner.json
scripts/lemma-school build/school/my-school '{"op":"enroll","learner":"second-learner","course":802,"revision":1}' --credential teacher.json
scripts/lemma-school build/school/my-school revoke-pair --credential teacher.json --token-hash PUBLIC_ADMISSION_SHA256

The private teacher handoff selects the principal and protected endpoint; command-line actor fields cannot override it. Secrets remain outside child arguments and logs. The new handoff inherits the same client port. After a clock-epoch migration, pair again through the operator-local authority because previous epoch credentials cannot extend expired access. Restart in the same epoch preserves admission while changing execution generation and fencing prior workers and uncommitted joins.

scripts/lemma-school build/school/my-school start --school my-school --actor owner --port 8790 --client-port 8791
scripts/lemma-school build/school/my-school status --school my-school --actor owner
scripts/lemma-school build/school/my-school pair --school my-school --actor owner --learner learner-a --to build/school/learner-a.private.json --client-port 8791
scripts/lemma-school build/school/my-school backup --school my-school --actor owner --to build/school/backup-NEW
scripts/lemma-school build/school/my-school fork --school my-school --actor owner --to build/school/independent-NEW --new-school independent-school --new-deployment independent-local
scripts/lemma-school build/school/my-school stop --school my-school --actor owner
scripts/lemma-school build/school/restored-NEW restore --school my-school --actor owner --from build/school/backup-NEW
scripts/lemma-school build/school/restored-NEW start --school my-school --actor owner --port 8790 --client-port 8791

start waits for an admitted status response before returning and records PID/start-tick/boot identity in transport.json; diagnostics are in transport.log. It cleans up its own failed launch. run remains the foreground equivalent. client-run --port 8791 exposes only /v1/client and is stopped through its foreground process. The protected endpoint takes a Bearer credential and bounded JSON, rejects filesystem paths, and supports revocation. Pairing does not itself enroll a learner or confer teacher grants; the school owner grants those separately through the maintained enrollment/grant operations. Re-pair after an unknown boot-domain change.

Configure and drain local inference workers

Lemma.School.LocalProvider represents the one local node, versioned worker configurations, declared resource reservations, controller health reports and drain state. Numerical jobs require an explicitly configured worker before leasing. The generic hosted job interface retains its school-wide quotas; it does not claim an RV64 worker capability. The registry is private operational state and is excluded from reusable definitions and independent clones.

scripts/lemma-school build/school/my-school '{"op":"node-config","school":"my-school","actor":"owner","node":"local","version":1,"provider":"local","profile":"core0-v0.5","capabilities":["school-linear-worker/1"],"maxWorkers":4,"memoryBytes":536870912,"storageBytes":67108864}'
scripts/lemma-school build/school/my-school '{"op":"provider-status","school":"my-school","actor":"owner"}'

Stage the audited worker image with artifact-put, then use its returned digest in worker-config. Required fields are worker ID, increasing version, node local, controller actor, profile core0-v0.5, imageSha256, capabilities ["school-linear-worker/1"], and the exact supported resources: cpuSlots:1, memoryBytes:134217728, inputBytes:88, outputBytes:48, scratchBytes:16384. Only a school administrator configures resources. The controller or operator reports worker-health with worker ID, current configVersion, current generation, status unknown, ready or offline, a bounded reason and verified artifact digests. Ready means that the authorized local controller reports the slot ready to launch. Actual VM boot/READY and inference remain separately observed evidence.

Before numerical lease admission, Lean checks profile, image identity, current readiness, drain state, exclusive worker ownership, node slot/memory reservations and actual availability of the job's artifact closure. Storage reserves each concurrent job's complete closure conservatively, including shared bytes; it is not a disk-free-space guarantee. Guest resources match the runner's one-vCPU, 128 MiB QEMU configuration. Host CPU enforcement, cgroups and remote attestation are unsupported. The maintained real-job and four-worker load scenarios configure these resources and retain their actual VM evidence.

For a configured worker named rv64-1, a drain blocks new assignments while permitting its current lease to finish:

scripts/lemma-school build/school/my-school '{"op":"worker-drain","school":"my-school","actor":"owner","worker":"rv64-1","draining":true}'
scripts/lemma-school build/school/my-school '{"op":"reconcile","school":"my-school","actor":"owner"}'

node-drain applies the same rule to node local. Set draining:false to resume admission. A lease binds the exact ready-report sequence. Any changed health report, including a ready-to-ready reason or artifact change, supersedes active leases; offline-to-ready cannot revive old ownership. Retrying the identical report preserves its epoch. Record actual VM READY as separate execution evidence rather than changing the launch report during a lease. Worker reconfiguration and an authority restart also require renewed readiness and reconciliation of superseded ownership. Node budget changes govern new leases while preserving existing reservations and admitted completion. Repeating identical configuration, health or drain reports is idempotent. Reconciliation converges without duplicating resources or jobs; generation and fence checks reject the old response.

Follow the source/authoring guide to import a catalogue, configure owner-controlled source locations, preview the same definition used by the learner and publish an immutable edition. The immediate sample uses explicitly redistributable material in FixtureUnit.lean; the source-derived binomial-square unit is distinct and cites the actual supplied collection. A teacher can inspect another learner only with an explicit evidence grant. Textbook possession grants no redistribution license.

The client guide covers enrollment, installed course packages, a fresh guest ASK, explicit school JOIN, help, typed submissions with separate guest observations, cancellation and due review. Drawing works with every optional modality absent. Independent activities reject assistance; unsupported mathematical proof is retained for teacher review. The exact polynomial checker handles its declared domain and does not certify arbitrary handwritten reasoning.

Learner goals, challenges and recommendation choices

The Study panel exposes Goal, Challenge, Override and History. Each declaration names an existing attempt or suggestion, its exact course edition and policy, a reason, and a stable request ID. A goal also carries newGoal. The learner can declare a new goal, ask for an interpretation to be reconsidered, or override a recommendation whose recorded policy permits it. The ordinary reader keeps the next activity under learner control. Ordered choice history preserves the original evidence, artifact references and actor/time provenance; checker results and published assessment rules retain their original interpretation.

After an enrolled learner has an attempt named attempt-1 in course 1, edition 1, policy 1, the equivalent maintained commands are:

scripts/lemma-school build/school/my-school '{"op":"goal-set","school":"my-school","actor":"learner","id":"goal-1","course":1,"revision":1,"policy":1,"reason":"I want to practise counterexamples before proof.","referenceKind":"attempt","reference":"attempt-1","newGoal":"Explain a counterexample independently."}'
scripts/lemma-school build/school/my-school '{"op":"learner-choices","school":"my-school","actor":"learner"}'

interpretation-challenge uses the same reference and reason fields, with a new request ID. suggestion-override requires referenceKind: "suggestion" and that suggestion's key; Lean checks its overrideAllowed field. Reasons admit 1–1024 UTF-8 bytes and goals 1–512 bytes. Retrying the identical request ID returns its original declaration. Reusing it for different content fails. A peer needs read on the learner to inspect this history and a separate correct grant to declare a change on their behalf. The school's operator retains explicit local authority. These records represent declared goals and choices; they establish no new mathematical verdict or measured learning effect.

Recovery and portable ownership

scripts/lemma-school build/school/my-school '{"op":"export","school":"my-school","actor":"owner","to":"build/school/my-backup"}'
# Stop the original authority before offline restoration.
scripts/lemma-school build/school/restored '{"op":"restore","school":"my-school","actor":"owner","from":"build/school/my-backup","offline":true}'
scripts/lemma-school build/school/my-school '{"op":"clone","school":"my-school","actor":"owner","to":"build/school/new-school","newSchool":"new-school","newDeployment":"local-b"}'

Export contains private operational records and the full required artifact closure. Current observation export consent is required; revoked or missing consent rejects the export. It is not a public reusable package. Offline restore copies bytes, retains historical progress, and increments generation so old leases cannot commit. The original must remain stopped: replication or coordination between two authorities with one deployment identity is unsupported. The logical scheduling clock binds explicit host-boot epochs. Restoration or opening after a different boot preserves old record times and rebases at the last committed scheduling time; unknown offline elapsed time is frozen. Same-boot elapsed time remains measurable. Worker generations and boot-relative deadlines reject stale ownership. Clock-domain changes invalidate bearer admissions and require pairing again. Future reviews can be delayed by unknown downtime; already-due reviews remain due. Fresh reusable package import and independent clone start an independent clock. External textbook manifests retain digests and require explicit owner source resolution after transfer.

To select an earlier committed history, add throughSequence to the export request, using the sequence returned by an acknowledged mutation. The export retains exactly records 1 through that number and only their required artifacts; zero selects an empty history, and an out-of-range or malformed selector fails. Omitting the selector exports the entire current history. Exact row identities, publication versions and earlier dependencies remain unchanged. Present authorization and present observation export consent govern disclosure, even when exporting a historical prefix. The manifest binds the selection, original record count, snapshot digest and copied artifact closure. Ordinary offline restore consumes either selection. This is temporal selection; per-learner filtering is unsupported. Restoring a historical prefix also rolls its grants and consents back to that point, so the operator must review and reconfigure permissions before resuming shared use.

Clone creates an independently named school and deployment with separate files, publications and explicitly reusable models. It excludes learners, private recordings, grants, jobs, source-path overrides and credentials. The versioned reusable package can also be exported and imported separately through maintained admission APIs. Credentials must be configured explicitly outside packages. gc reclaims unreferenced artifact/staging bytes and ignored incomplete transactions; committed references remain pinned.

The selected commit protocol stages/hashes artifact bytes, barriers the file before rename, and barriers both directories before reference publication. It barriers each new snapshot file, atomically renames it, and barriers its directory and parent before acknowledgement. Barrier failure stops the authority. Recovery validates the full closure; the cached long-lived authority serves ordinary queries without rehashing and recommitting all history merely because uptime advances. Mutations remain bounded complete snapshots. These guarantees depend on the documented local filesystem/device barrier assumptions; physical power-loss and replicated availability remain unqualified. See the exact binding and version1-to-version2 migration.

Training, inference and validation

See the exact numerical/worker contract. A hosted Lean Float64 trainer fits a two-feature linear synthetic review-risk scorer, saves complete resumable state and quantizes parameters to signed Q10. The actual unchanged RV64 image reads parameters and features at runtime, returns a Q20 score, and its raw response plus source/audit/execution artifacts are committed through fenced school jobs. Only a selected published release can inform an allowed suggestion; the explainable review policy remains visible fallback. Synthetic performance is pipeline evidence, not learning efficacy.

Configure, evaluate, publish and roll back a school scorer

The maintained training entry point accepts an independently supplied permitted dataset and a bounded optimizer configuration. The small configuration example selects model9001, learning rate0.05 and momentum0.2. Supported limits remain two finite features in [-1,1], independent labels in [0,1], three parameters in [-8,8], batches of four, learning rate(0,0.25], momentum[0,0.95], fixed disjoint groups and at most100,000 updates. No arbitrary tensor/compiler capability is implied.

scripts/lemma-school training fixture build/school/dataset-NEW
scripts/lemma-school training train-config build/school/dataset-NEW build/school/checkpoint-NEW.json build/school/model-NEW 32 examples/school/training-config.json
scripts/lemma-school training evaluate-config build/school/dataset-NEW build/school/checkpoint-NEW.json build/school/evaluation-NEW examples/school/training-config.json
scripts/lemma-school build/school/my-school publish-training --school my-school --actor owner --directory build/school/model-NEW --dataset build/school/dataset-NEW --checkpoint build/school/checkpoint-NEW.json --configuration examples/school/training-config.json --rights 'Original generated numeric fixture; CC0 rows; owner-controlled parameters' --reusable
scripts/lemma-school build/school/my-school models --school my-school --actor owner
scripts/lemma-school build/school/my-school select-model --school my-school --actor owner --version 9001
scripts/lemma-school build/school/my-school rollback-model --school my-school --actor owner --version 9001 --reason 'Return to the previous immutable release after comparison'

Use a new configuration/model identity for a distinct immutable release. Repeating train-config with the same checkpoint and a higher total step resumes exact parameter/velocity bits, cursor, epoch, dataset, configuration and implementation identity. Changing configuration while reusing that checkpoint rejects. Evaluate-config verifies the same split and writes results without another optimizer update. The checkpoint/output writer uses the same file and directory barriers; physical power-loss qualification remains separate. A supplied lemma-permitted-risk-dataset/v1 manifest retains explicit source, grant, label origin, transformation SHA256, supported feature order, split identities and byte digests. Permission assertions are declarations requiring the operator's actual rights; the software does not clear private learner data or textbook rights.

Publish-training delegates checkpoint/parameter/dataset/config identity checks and artifact-before-reference publication to Lean. It runs either through the existing running owner endpoint or local mutex. Models status and selection/rollback retain every earlier release; selecting an older release cannot reinterpret an earlier inference or assessment. Source-bound synthetic comparison reports the explainable fixed baseline beside each model and makes no educational improvement claim.

recommendation-input prepares at most eight available independent assessments for the selected learner/publication. It keeps exact checker outcomes and versioned human judgments distinct, preserves their sequences and availability times, and quantizes error fraction and a bounded one-week gap to the existing worker profile. With no assessed independent work, it records missingness and retains the permitted authored baseline; admission rejects a numerical job for that missing input. A prepared job must match the immutable learner/activity/publication/features/mask. Actual RV64 output is committed through the existing fenced job path before it can supply a suggestion. This is a review selector with an explainable fallback, not an explanation generator or assessment authority.

Ordinary permitted help now consumes an eligible committed suggestion through lemma-tutor-selection/1. The selected model, learner, activity, publication, policy, preparation and completed job must agree, the independent assessment evidence must remain unchanged, and the suggestion must be at most one scheduling day old. The response retains job, result, model and preparation provenance. A score at least524288Q20 prefixes the authored hint with “Review this hint, then try practice.”; a lower score prefixes “Try reconstruction, then compare this hint.”. Missing, stale, replaced or unselected inputs retain the exact authored hint. The combined text must fit the existing196-byte packet bound; long hints retain the original authored text. These are optional practice actions, with no change to checking or assessment authority.

A help decision commits its exact packet before transport. Retrying the same admitted decision reads and verifies that original artifact, including after model rollback; it cannot silently generate a different explanation under the old decision ID. A fresh decision after rollback uses the current eligible selector or authored baseline. Transport, guest raster acceptance and controller observations retain their separate scopes. Numerical selection does not establish that the learner saw the advice, followed it or learned from it.

The focused scripts/check_school_training_workflow.py scenario reuses two genuinely trained configurations, prepares features from a declared written-work fixture and actual versioned human assessment, runs the unchanged audited RV64 image in two fresh processes, commits each result, selects and rolls back releases, and rejects using the unselected result. It then exercises protected principal admission and the ordinary help API: committed advice changes the packet, rollback preserves an old decision's retry bytes, a fresh decision falls back, and reselection restores eligible advice. ASK and raw receipt inputs in that component scenario are explicitly synthetic. It complements the actual worker-loss/four-worker scenarios and the training SIGKILL/resume check. Browser/native visible delivery and educational qualification remain separate.
