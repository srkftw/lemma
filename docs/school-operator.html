Lemma documentation

Run and develop a local Lemma school

Foundation 0.1.0 runs one school authority on the owner's machine. School decisions, authorization, authoring, training and recovery are maintained Lean. The authority is a hosted native Lean program using the upstream host runtime. Its separately audited inference worker is freestanding RV64. No remote account, model API or paid service is required.

Use the native LemmaSim school workspace to switch between Study, Teach, Operate and Develop. It presents the same commands below and delegates drawing, course installation, joining and visible assistance to the actual guest bridge. The local OS caller supplies the actor identity; access to the filesystem and loopback service is trusted. This is a development authentication boundary, not a public authenticated service.

Initialize, run and restart

From the repository root, choose a fresh ignored directory. The launcher builds with the pinned environment and takes the school's OS mutex. Every request declares school and actor; the owner can grant specific action/resource capabilities to another identity. A learner can enroll or inspect their own work without a general administrator grant. Attempt, observation and client-session identifiers are currently school-wide: use unique identifiers for separate learners and submissions; reusing one for different work fails with an idempotency conflict.

scripts/lemma-school build/school/my-school '{"op":"init","school":"my-school","actor":"owner","deployment":"local-a","provider":"local"}'
scripts/lemma-school build/school/my-school '{"op":"status","school":"my-school","actor":"owner"}'
scripts/lemma-school build/school/my-school run --port 8790

The last command exposes only http://127.0.0.1:8790/v1/command. The supported transport is bounded JSON over loopback HTTP or serialized local commands. A second writer fails the OS lock. The native child inherits that lock, so abrupt transport-parent termination cannot admit a competing writer while the child is still committing. Stop through the panel or an HTTP stop command; restart with the same run command. Each long-lived authority start commits a new execution generation before accepting work. Raw .lake/build/bin/school is an internal serial binding; public callers use the mutex launcher/transport.

Default budgets are 10,000 records, 8 MiB per artifact, 32 outstanding jobs with four queue slots reserved for interactive work, four leased workers, three retries and 60-second maximum leases. Supply a complete budgets object at initialization to change admitted limits; Lemma/School/Model.lean and Store.validBudgets define exact fields and hard caps. Only the local provider is implemented; unsupported providers fail. Status reports identity, generation, budgets, jobs and committed artifact closure. Reconciliation requeues expired or prior-generation leases within the retry budget and cancels exhausted jobs; repeating it without new failures does not duplicate work.

Configure and drain local inference workers

Lemma.School.LocalProvider represents the one local node, versioned worker configurations, declared resource reservations, controller health reports and drain state. Numerical jobs require an explicitly configured worker before leasing. The generic hosted job interface retains its school-wide quotas; it does not claim an RV64 worker capability. The registry is private operational state and is excluded from reusable definitions and independent clones.

scripts/lemma-school build/school/my-school '{"op":"node-config","school":"my-school","actor":"owner","node":"local","version":1,"provider":"local","profile":"core0-v0.5","capabilities":["school-linear-worker/1"],"maxWorkers":4,"memoryBytes":536870912,"storageBytes":67108864}'
scripts/lemma-school build/school/my-school '{"op":"provider-status","school":"my-school","actor":"owner"}'

Stage the audited worker image with artifact-put, then use its returned digest in worker-config. Required fields are worker ID, increasing version, node local, controller actor, profile core0-v0.5, imageSha256, capabilities ["school-linear-worker/1"], and the exact supported resources: cpuSlots:1, memoryBytes:134217728, inputBytes:88, outputBytes:48, scratchBytes:16384. Only a school administrator configures resources. The controller or operator reports worker-health with worker ID, current configVersion, current generation, status unknown, ready or offline, a bounded reason and verified artifact digests. Ready means that the authorized local controller reports the slot ready to launch. Actual VM boot/READY and inference remain separately observed evidence.

Before numerical lease admission, Lean checks profile, image identity, current readiness, drain state, exclusive worker ownership, node slot/memory reservations and actual availability of the job's artifact closure. Storage reserves each concurrent job's complete closure conservatively, including shared bytes; it is not a disk-free-space guarantee. Guest resources match the runner's one-vCPU, 128 MiB QEMU configuration. Host CPU enforcement, cgroups and remote attestation are unsupported. The maintained real-job and four-worker load scenarios configure these resources and retain their actual VM evidence.

For a configured worker named rv64-1, a drain blocks new assignments while permitting its current lease to finish:

scripts/lemma-school build/school/my-school '{"op":"worker-drain","school":"my-school","actor":"owner","worker":"rv64-1","draining":true}'
scripts/lemma-school build/school/my-school '{"op":"reconcile","school":"my-school","actor":"owner"}'

node-drain applies the same rule to node local. Set draining:false to resume admission. A lease binds the exact ready-report sequence. Any changed health report, including a ready-to-ready reason or artifact change, supersedes active leases; offline-to-ready cannot revive old ownership. Retrying the identical report preserves its epoch. Record actual VM READY as separate execution evidence rather than changing the launch report during a lease. Worker reconfiguration and an authority restart also require renewed readiness and reconciliation of superseded ownership. Node budget changes govern new leases while preserving existing reservations and admitted completion. Repeating identical configuration, health or drain reports is idempotent. Reconciliation converges without duplicating resources or jobs; generation and fence checks reject the old response.

Author and study

Follow the source/authoring guide to import a catalogue, configure owner-controlled source locations, preview the same definition used by the learner and publish an immutable edition. The immediate sample uses explicitly redistributable material in FixtureUnit.lean; the source-derived binomial-square unit is distinct and cites the actual supplied collection. A teacher can inspect another learner only with an explicit evidence grant. Textbook possession grants no redistribution license.

The client guide covers enrollment, installed course packages, a fresh guest ASK, explicit school JOIN, help, typed submissions with separate guest observations, cancellation and due review. Drawing works with every optional modality absent. Independent activities reject assistance; unsupported mathematical proof is retained for teacher review. The exact polynomial checker handles its declared domain and does not certify arbitrary handwritten reasoning.

Learner goals, challenges and recommendation choices

The Study panel exposes Goal, Challenge, Override and History. Each declaration names an existing attempt or suggestion, its exact course edition and policy, a reason, and a stable request ID. A goal also carries newGoal. The learner can declare a new goal, ask for an interpretation to be reconsidered, or override a recommendation whose recorded policy permits it. The ordinary reader keeps the next activity under learner control. Ordered choice history preserves the original evidence, artifact references and actor/time provenance; checker results and published assessment rules retain their original interpretation.

After an enrolled learner has an attempt named attempt-1 in course 1, edition 1, policy 1, the equivalent maintained commands are:

scripts/lemma-school build/school/my-school '{"op":"goal-set","school":"my-school","actor":"learner","id":"goal-1","course":1,"revision":1,"policy":1,"reason":"I want to practise counterexamples before proof.","referenceKind":"attempt","reference":"attempt-1","newGoal":"Explain a counterexample independently."}'
scripts/lemma-school build/school/my-school '{"op":"learner-choices","school":"my-school","actor":"learner"}'

interpretation-challenge uses the same reference and reason fields, with a new request ID. suggestion-override requires referenceKind: "suggestion" and that suggestion's key; Lean checks its overrideAllowed field. Reasons admit 1–1024 UTF-8 bytes and goals 1–512 bytes. Retrying the identical request ID returns its original declaration. Reusing it for different content fails. A peer needs read on the learner to inspect this history and a separate correct grant to declare a change on their behalf. The school's operator retains explicit local authority. These records represent declared goals and choices; they establish no new mathematical verdict or measured learning effect.

Recovery and portable ownership

scripts/lemma-school build/school/my-school '{"op":"export","school":"my-school","actor":"owner","to":"build/school/my-backup"}'
# Stop the original authority before offline restoration.
scripts/lemma-school build/school/restored '{"op":"restore","school":"my-school","actor":"owner","from":"build/school/my-backup","offline":true}'
scripts/lemma-school build/school/my-school '{"op":"clone","school":"my-school","actor":"owner","to":"build/school/new-school","newSchool":"new-school","newDeployment":"local-b"}'

Export contains private operational records and the full required artifact closure. Current observation export consent is required; revoked or missing consent rejects the export. It is not a public reusable package. Offline restore copies bytes, retains historical progress, and increments generation so old leases cannot commit. The original must remain stopped: replication or coordination between two authorities with one deployment identity is unsupported. The default monotonic clock is tied to the host boot. Operational restoration is currently qualified only within that clock domain: a different host or reboot with lower uptime rejects clock rollback and may remain unusable until its clock catches up. Cross-boot/cross-host historical restore needs an explicit logical-clock rebasing protocol and is unsupported. Fresh reusable package import and independent clone start a new clock and are unaffected. External textbook manifests retain digests and require explicit owner source resolution after transfer.

To select an earlier committed history, add throughSequence to the export request, using the sequence returned by an acknowledged mutation. The export retains exactly records 1 through that number and only their required artifacts; zero selects an empty history, and an out-of-range or malformed selector fails. Omitting the selector exports the entire current history. Exact row identities, publication versions and earlier dependencies remain unchanged. Present authorization and present observation export consent govern disclosure, even when exporting a historical prefix. The manifest binds the selection, original record count, snapshot digest and copied artifact closure. Ordinary offline restore consumes either selection. This is temporal selection; per-learner filtering is unsupported. Restoring a historical prefix also rolls its grants and consents back to that point, so the operator must review and reconfigure permissions before resuming shared use.

Clone creates an independently named school and deployment with separate files, publications and explicitly reusable models. It excludes learners, private recordings, grants, jobs, source-path overrides and credentials. The versioned reusable package can also be exported and imported separately through maintained admission APIs. Credentials must be configured explicitly outside packages. gc reclaims unreferenced artifact/staging bytes and ignored incomplete transactions; committed references remain pinned.

The local commit protocol stages and verifies artifact bytes, then closes and atomically renames a checksummed snapshot before acknowledgement. Actual SIGKILL tests cover artifact staging, before commit, after commit before acknowledgement, daemon restart and retry. This demonstrates process-termination recovery with a functioning filesystem. Host-crash, power-loss, fsync, replication and general schema migration remain unimplemented.

A runnable Lean extension

examples/school/QuickReview.lean uses Authoring.Unit directly to change review policy and requires a new immutable edition. The editor JSON, Lean DSL, preview, compiler and client share that representation. Unsupported visual/declarative constructs produce diagnostics rather than silently becoming different content.

nix develop --no-write-lock-file --command lake env lean --run \
  examples/school/QuickReview.lean examples/school/source-derived-client-unit.json \
  build/school/my-quick-review.json 3
scripts/lemma-school curriculum preview build/school/my-quick-review.json
scripts/lemma-school curriculum compile build/school/my-quick-review.json build/school/my-quick-review.lcp

Publish the generated JSON with the normal Teach panel, enroll in edition 3, and install/open it through the normal LemmaSim bridge. Earlier attempts and reviews retain their original edition and policy. This short review delay tests software scheduling and establishes no long-term retention result. The simulator uses the canonical device contract; physical sensing, display conformance and body-connected behavior remain unqualified.

For browser experimentation, begin with the existing simulator workflow and shared LemmaSim plan, then trace the same device bindings to the canonical machine contract above. The school acceptance here uses the native backend; browser delivery/performance and physical qualification need their own source-bound runs.

Training, inference and validation

See the exact numerical/worker contract. A hosted Lean Float64 trainer fits a two-feature linear synthetic review-risk scorer, saves complete resumable state and quantizes parameters to signed Q10. The actual unchanged RV64 image reads parameters and features at runtime, returns a Q20 score, and its raw response plus source/audit/execution artifacts are committed through fenced school jobs. Only a selected published release can inform an allowed suggestion; the explainable review policy remains visible fallback. Synthetic performance is pipeline evidence, not learning efficacy.

nix develop --no-write-lock-file --command python3 scripts/build_school.py --output-dir build/school/host-UNUSED
nix develop --no-write-lock-file --command python3 scripts/check_school.py --production build/school/host-UNUSED/production.json --work-dir build/school/host-check-UNUSED
nix develop --no-write-lock-file --command python3 scripts/check_school_training.py --work-dir build/school/training-UNUSED
nix develop --no-write-lock-file --command python3 scripts/build_school_worker.py --output-dir build/school/worker-UNUSED --opt-level O2

Use the worker/job/load checker help and the checkpoint for exact retained input and image paths. Hosted validation does not substitute target execution, real corpus ingestion or visible client delivery. Larger database engines, resident large models, automatic differentiation coverage, distributed arrays, accelerators, remote node membership, placement, authenticated providers and replicated availability need their own implementation and fault/partition gates.
