Ordering and continuation

Frozen metadata and its durable pending pointer are separate Store transactions in namespace 2. Metadata must Commit before its pointer; both actual receipts precede the first transport byte. The original ink objects remain in the captured document namespace 1 or2. Namespace2 object0x5350000000000001 retains pending, cancelled or acknowledged state, including the bound school commit identity. Frozen metadata keys0x5351xxxxxxxxxxxx remain append-only, including tombstones.

One pump issues at most one IPC transition or one 16-byte Console data record. Begin Busy and unaccepted read Busy yield and retry without replacing the frozen work. An interactive Save requests suspension before its next Begin, waits until the queue writer is inactive, and continues while the helper finishes an actual Abort of uncommitted staging. A pending Commit always reaches its original terminal poll. Resume starts the same frozen metadata upload. Cancellation suppresses the remaining stream and records withdrawal; it does not retract work already admitted by the school.

Restart reads the global pending pointer and frozen metadata through guest Store calls, validates the original workspace/header and reconstructs the raw chunk lengths from the original objects. Cold recovery is distinct from exact same-backend checkpoint continuation. Failed or uncertain queue Commit never creates a queue receipt or transport output. An unreferenced metadata object can remain after interruption between metadata and pointer Commit; it was not acknowledged as queued.
