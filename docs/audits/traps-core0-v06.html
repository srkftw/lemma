Trap entry copies MIE into MPIE, clears MIE, records prior privilege in MPP, and writes the faulting/interrupted PC to MEPC. MRET restores MIE from MPIE, sets MPIE, and resets MPP to the least supported privilege. Consequently raw pre/post mstatus equality is not a valid oracle. ECALL from M-mode has cause 11 and zero trap value. EBREAK has cause 3; its trap value may be zero or its PC. Pinned QEMU reports the PC for ordinary EBREAK. Semihosting is not enabled, and the probe is not the special three-instruction semihosting sequence. The pinned TCG feature normalization explicitly disables both Smrnmi and Smdbltrp. The exact -cpu rv64 launch therefore reaches the software latch on the nested-ECALL fixture; this must not be generalized to a CPU with hardware double-trap redirection enabled.

Closed compiler and effect contract

The additive profile is core0-v0.6; earlier profiles retain their contracts. The only new source Actions are trapEcall, trapBreakpoint, trapUnexpectedEcall, and trapIllegalInstruction, under Lemma.Core0.Memory.Action. Exact identities/signatures and immediate checked continuations are required. No source-supplied encoding, address, CSR, exception cause, extern registration, or runtime callback is admitted.

The Actions have separate transitive sync-trap and machine-state effects. Their four closed machine declarations return one i64 context mask; the returning Action receives status zero and that mask. Unexpected/illegal fixture operations do not return in correct execution. The old finite RAM/UART models reject trap Actions explicitly; they do not simulate hardware traps as success. All ordinary source algorithms still use genuine elaboration, checked Action IR, validated CFG/LLVM, and integer LP64 RV64 code.

Frame, stack, and return

The machine representation is typed Lean instructions, not an embedded assembly program. Startup masks mie and MSTATUS.MIE before other work, establishes the existing boot/BSS contract, initializes canaries, installs a four-aligned direct mtvec, and places the private trap-stack top in mscratch.

Private regions do not add IDs to the ordinary checked-memory catalog. The 288-byte aligned frame stores x1 through x31 at (register_number - 1) * 8, including interrupted SP at offset 8 and t0 at 32. CSR offsets are mstatus 248, mepc 256, mcause 264, mtval 272, and mie 280.

Entry exchanges SP with mscratch and branches to stackless fatal status 19 if the received value is zero. It allocates the frame, saves t0 before using it, and exchanges the interrupted SP out of mscratch while setting that latch to zero. All remaining integer registers are saved before use. GP/TP are saved, then zeroed before compiled dispatch; the artifact audit must reject any GP/TP use in compiled code. Floating/vector state is excluded by the target profile.

The compiled dispatcher receives nine scalar words: cause, PC, mstatus, tval, mie, and both authorized site/continuation pairs. Its ninth argument occupies offset zero of a separate 16-byte aligned outgoing frame. The two-word Action return is status in a0 and explicit resume PC in a1. A nonzero status goes to the bounded fatal finisher (18); success installs the approved PC, restores captured/validated mstatus and mie, and restores all integer registers.

The final tail restores t0, releases the frame, resets mscratch to trap-stack top, reloads SP from its saved slot with SP as its own base, and executes MRET. The 16,352-byte usable trap stack must cover the 288-byte frame, 16 outgoing bytes, and the measured compiled dispatch chain, at most 16,048 bytes. Canaries are observations, not substitutes for a static/resource bound.

Non-nesting is a software contract. Masking interrupts does not suppress synchronous exceptions. The zero latch catches faults during dispatch; a real ECALL from compiled dispatch exercises this path. Entry before latch clearing and the final aligned SP load/MRET after latch resetting presume fault-free fixed mapped RAM/CSR accesses, MPRV clear, an approved M-mode continuation, and no NMI. The implementation does not claim exhaustive double-fault classification outside that premise or a hardware double-trap extension.

Source policy and target observations

The compiled source requires (mstatus & 0x21888) == 0x1800 and mie == 0. Only cause 11 at the exact ECALL site with tval zero, or cause 3 at the exact EBREAK site with tval zero/PC, may resume. It selects explicit continuation symbols; each approved instruction is independently checked to occupy four bytes. Unknown causes/PCs produce five bounded source-encoded UART diagnostic frames and fatal status 18. Nested entry produces status 19 without another stack access or compiled call. The finisher uses the declared SiFive-test MMIO.

Returning probes save the actual ABI caller in private RAM, initialize all 31 integer registers to distinct sentinels (SP to a valid private stack), execute the real trap, and snapshot all 31 registers before comparison clobbers any of them. Failure bits 0–30 correspond to x1–x31; six canary pairs occupy bits 31–36. Caller ABI state is restored before returning the mask. The quarantined restore-s3-from-s4 mutation substitutes the S4 slot for S3 on return. Distinct sentinels require mask 0x40000; this is intended to boot, dispatch, and return, not fail compilation or artifact audit.

The foreground computes a runtime-seeded wrapping 64-bit mix in both a control fold and an interrupted fold, with zero through 64 iterations and an ECALL plus EBREAK per interrupted iteration. Runtime seed/count/scenario bytes are supplied only after building the image. Fourteen software-denial checks run with the vector active; successful denial requires the expected status/value, unchanged trap count, and unchanged scratch guard. Normal output includes the actual checksum, trap count, denial count, and context mask. The host checks an independent arithmetic oracle and retained raw frames.

TrapPolicyProbes.lean directly evaluates 20 source predicates and checks two conditional local policy lemmas; their dependencies are propext and Quot.sound. These are not a proof of trap entry, the frontend, LLVM, or full compiler correctness. Register/canary target tests, static audits, local lemmas, and emulator behavior remain distinct evidence.
