Fast development loop

Run from the project checkout with an unused output directory:

python3 scripts/ci_preflight.py --output-dir build/ci/local-preflight-1

Preflight runs metadata plus scaffold, Core0 harness and CI policy suites using the host Python standard library. It fails on empty suites, failures, import errors or skipped tests and retains scoped logs/results. The hosted job has a three-minute command limit and five-minute job limit. It does not realize Nix, build Lean, generate RV64 artifacts or boot QEMU. A preflight pass is host feedback only. Full metadata repeats the suites in the pinned environment.

Open a draft PR early to receive the independent parallel acceptance jobs. For focused compiler/guest feedback, use the README's build/audit/run and lane interfaces in nix develop --no-write-lock-file; choose new evidence paths and retain failures. Final qualification requires a clean committed candidate and the separate inherited and Task 004 interfaces. Do not move successful reports across source revisions. A new project directory with a warm Nix store is a clean project build, not a cold toolchain observation.

Dependencies, artifacts and trust

No project outputs, PASS reports, guest observations or qualification outputs are cached. Existing Nix binary substitution and source realization remain mandatory on cache misses. No custom Actions dependency cache was added: the selected existing Lean/LLVM/LLD/stock-QEMU closure alone measured 7,204,814,352 NAR bytes (6.71 GiB), excluding the additional devshell tools, pinned Lean source and derived LemmaSim QEMU. This smaller host-tool candidate merits a transfer benchmark; no Actions cache hit/miss measurement or trusted main cache producer exists in this cleanup.
