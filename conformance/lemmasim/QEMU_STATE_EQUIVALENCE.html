Source reason for the two fields

The pinned source archive is QEMU 11.1.1, SHA256 079ffbff8a7111bbc89022107cbabf3bbfd614d5fc9d7cc675991196aca12482, realized as /nix/store/5fncyn7ha91mjhrxsl6id2wdi6zlgbnb-qemu-11.1.1.tar.xz by the repository Nixpkgs pin 7dd199b0e2993e37b4775ed66b1c291699608c9f. The following are direct inspections of that source, rather than deductions from the differing values:

  • system/cpu-timers.c:43–135 defines cpu_ticks_offset in host CPU-cycle units and cpu_clock_offset in host monotonic nanoseconds. Start/stop adds cpu_get_host_ticks() / get_clock() so they measure elapsed host running time. Different host execution durations necessarily produce different values. Lines 202–234 serialize them in timer version 2, around an unused eight-byte field, and separately serialize the two instruction-clock fields in timer/icount version 1.
  • accel/tcg/tcg-accel-ops.c:211–214 selects icount_get for both virtual clock and elapsed guest ticks when instruction counting is enabled. system/cpus.c:225–256 dispatches those selected operations. util/qemu-timer.c:650–662 sends QEMU_CLOCK_VIRTUAL through that virtual clock; the host-offset clock belongs to QEMU_CLOCK_VIRTUAL_RT.
  • accel/tcg/icount-common.c:448–468 creates the realtime warp timer only with sleep enabled. A numeric shift enables precise counting and returns before creating the adaptive realtime adjustment timers. With sleep and alignment disabled here, idle advancement follows virtual deadlines; elapsed host offsets do not drive it. The fast stop-boundary guard in tooling/lemmasim/apply_qemu.py prevents further idle advancement after a bounded run has requested its stop.
  • target/riscv/tcg/csr.c:1298–1303 reads the admitted cycle/instret counters from icount_get / icount_get_raw. Time reads use the CLINT callback; hw/intc/riscv_aclint.c:53 derives that from QEMU_CLOCK_VIRTUAL. The selected scalar CPU has no admitted filtered-PMU extension.
  • All custom pen/paper/block timers and timestamps in sim/host/lemma_qemu.c and lemma_fast_block.c, plus the selected UART timers in hw/char/serial.c, use QEMU_CLOCK_VIRTUAL. The fast machine excludes the unused RTC/PCI/other virt devices. Host clock statistics may be printed by a host observer such as info jit; such output is distinct from guest time.
